# 工作模式 AI Agent V1 需求规格

状态：Draft，等待用户评审
日期：2026-08-27
首发平台：macOS、Windows
兼容策略：工作模式第一版，不要求兼容旧工作任务数据；普通聊天数据与行为不得受影响

## 1. 产品目标

把当前“会调用少量工具的聊天回复”改造成可持续工作的桌面 Agent：用户只需安装并运行本 App，即可一次授权多个本地文件夹，让群聊或私聊中的 AI 角色读取、修改和验证真实文件；任务可跨页面运行、跨重启手动恢复，并能围绕旧任务连续追问、修改原文件和撤销变更。

成功标准不是“模型回复了”，而是：任务状态可见、工具结果真实、错误可恢复、权限边界清楚、产物可验证、修改可撤销。

## 2. 当前基线与已确认问题

| 现状 | 证据 | 用户影响 |
|---|---|---|
| 工作任务由 `ChatRoomPage` 持有 | 页面 `dispose` 会停止工作会话并注销 workspace | 离开聊天页后任务无法继续 |
| 审批期间的新输入会取消旧任务 | `work_mode_task_lifecycle_test.dart` 明确测试 “new input cancels the old approval” | 追问和补充容易变成新任务或丢失旧任务连续性 |
| 群聊执行者是“被 @ 的第一个，否则第一个可用角色” | `WorkModePolicy.selectExecutor` | 无法按产品、开发、测试等职业能力自动分工 |
| 工作区是 App 自动创建的会话目录 | `WorkModeWorkspaceService.loadOrCreate` | AI 不能操作用户指定的真实项目文件夹 |
| 读目录、读文件、浏览器和每次写入都逐次审批 | `WorkModePolicy.requiresApproval` | 操作被弹窗切碎，任务难以连续执行 |
| 命令只有少量固定白名单 | bridge 仅允许 `flutter analyze/test` 等少数命令 | 不具备通用 Agent 终端能力 |
| Agent 主循环固定 12 步、LLM 120 秒、工具 40 秒 | `AgentRuntime` 常量 | 稍复杂任务容易被硬上限中断 |
| 工具协议依赖多套正则兜底 | `AgentRuntime` 2558 行、`ToolRequest` 多种 XML/JSON 变体 | 模型格式稍有变化就会失败或误判 |
| 进度是聊天中的临时气泡 | `_upsertAgentProgressMessage` | 过程、审批、日志、结论混在消息流中 |
| 当前无 Key 搜索只是 DuckDuckGo Instant Answer | 实测“Flutter 最新稳定版本”返回 0 条 | 大多数真实网页查询无结果 |
| 工作模式附件只拼文本描述 | `AgentAttachmentContext` | 支持视觉的角色也无法真正分析图片 |
| 没有任务级快照与撤销 | 当前只保留已写文件 | 停止、失败或不满意后无法安全恢复 |

现有定向测试与 `flutter analyze` 均通过，但它们验证的是上述旧规则，不代表新需求已满足。

## 3. 已确认的产品原则

1. 文件夹授权是 App 全局授权，不绑定角色或单个会话。
2. 用户可授权多个文件夹；所有工作模式会话默认可访问全部已授权文件夹。
3. 同一会话同一时刻只运行一个任务；全 App 最多并行两个任务。
4. 群聊中每次只允许一个角色实际执行；多阶段任务可由不同角色依次接力。
5. 普通读取与只读联网自动执行；本地或外部状态变更按任务范围审批。
6. 工作模式采用应用级路径和命令限制，不承诺 OS 级强沙箱。
7. 任务过程使用独立、非模态、可折叠的执行面板；隐藏面板不停止任务。
8. 关闭 App 时任务中断；重开后由用户手动点击继续。
9. 任务、事件日志与撤销快照保存 30 天；快照默认总上限 2 GB。
10. 默认不运行完整测试或构建，只自动执行轻量检查；测试/构建需用户明确要求。
11. 普通聊天、自动群聊和主动私聊行为保持不变。

## 4. 核心用户流程

### 4.1 首次授权文件夹

1. 用户从设置页或任务面板点击“添加文件夹”。
2. App 打开系统文件夹选择器。
3. 用户选择文件夹后，App 展示规范化路径、可执行能力，以及“必要文件内容会发送给角色配置的云端模型 API”的说明。
4. 用户确认一次后，授权在 App 重启后仍保留。
5. 设置页可查看、添加、移除授权文件夹。

当 Agent 需要尚未授权的路径时，任务必须暂停并打开同一授权流程；授权成功后从原步骤继续，不重新开始任务。

### 4.2 发起与连续追问

1. 用户在工作模式会话中发送请求。
2. 请求持久化为任务并进入全局调度器。
3. 如果同一会话已有任务，新增请求排队，旧任务不得被取消或覆盖。
4. 当前任务完成后，排队请求自动开始。
5. 后续“修改刚才文件”“继续完善”等请求必须继承同一会话的消息、任务摘要、产物路径、工具结果和角色交接记录。
6. 修订请求默认覆盖原文件并创建可撤销快照；只有明确要求新建时才自动生成新路径。

上下文边界：同群角色共享群内工作上下文；私聊只继承该私聊上下文，不读取其他私聊或群聊的任务内容。

### 4.3 群聊角色选择与接力

- 用户 `@角色` 时，优先由被指定角色执行。
- 未 `@` 时，根据当前请求、会话上下文、角色名称、职业、人物提示词、标签和可用 API 自动选择最适合的角色。
- 一个请求包含“需求 → 开发 → 测试”等阶段时，系统生成可见的角色接力计划。
- 任一时刻只有一个角色拥有执行权；前一角色完成阶段并写入交接摘要后，下一角色才能开始。
- 不得让两个角色同时修改同一工作目录。

### 4.4 执行面板

执行面板为非模态底部面板：

- 默认展开，实时显示任务、当前角色、阶段、步骤、工具调用、命令输出、错误和结论。
- 可最小化为全局状态胶囊或进度条，也可隐藏；任务继续运行。
- 从任意页面都能重新打开正在运行或等待处理的任务。
- “停止”与“隐藏”是两个独立动作。
- 面板中不得展示模型私有思维链；只展示可核验的行动摘要、输入范围、工具输出和结论。
- 完成后展示文件差异、轻量检查结果、未验证项、“继续追问”和“一键撤销”。

### 4.5 写入审批与撤销

1. 首次变更前，面板列出预计创建、修改、重命名和删除的文件。
2. 用户一次确认后，该任务只可在已批准范围内继续写入。
3. 新增范围必须补充确认。
4. 构建或安装等无法精确预测全部文件的命令，展示命令、已知文件和可能影响目录，并标注不确定范围。
5. 设置中可关闭普通创建/修改前确认；删除文件、无法安全恢复的覆盖，以及“无快照继续”始终确认。
6. 变更直接写入真实目录；写前创建快照，任务完成后提供差异和一键撤销。
7. 点击停止时终止模型请求和子进程，保留已产生的修改并提供撤销，不自动回滚。

### 4.6 错误、澄清与恢复

- 需求不明确或存在高风险选择时，任务暂停并一次只问一个具体问题；回答后从原步骤继续。
- 模型格式错误、瞬时网络错误和工具失败先自动重试，并可尝试安全的替代路径。
- 连续失败后暂停，必须说明失败阶段、原始安全错误分类、已重试次数、已完成内容和建议动作。
- 不得自动切换角色的模型/API；由用户选择是否换模型后继续。
- App 崩溃或关闭后保留检查点；下次启动显示“继续/放弃”，不自动联网恢复。
- 达到 100 个 Agent 动作或 60 分钟任一软上限时暂停，展示当前结果并询问是否继续；确认后获得新的额度。

## 5. 功能需求

### FR-01 全局文件夹授权

- 支持 macOS、Windows 系统文件夹选择器。
- 多文件夹授权持久化；默认供全 App 的工作模式访问。
- 每次访问前使用规范化真实路径校验，Windows 比较不区分大小写。
- 符号链接目标超出授权根目录时视为未授权路径，暂停请求新增授权。
- 文件夹不存在、移动或访问失败时标记失效并要求重新授权。
- 移除授权不会删除文件，只会阻止后续 Agent 访问。

### FR-02 文件读取与分析

- 文本和代码：列目录、按需搜索、分段读取，不预建全盘语义索引。
- PDF、DOCX、XLSX：读取和分析，复用现有本地解析能力。
- 图片：交给支持视觉的当前角色模型分析；当前模型不支持时暂停并让用户选择其他视觉角色/模型。
- 音频和视频不在 V1 范围。
- PDF、Office 和图片可移动、重命名或删除，但 V1 不编辑其内部二进制内容，也不承诺生成这些二进制格式。
- 默认阻止读取或上传 `.env`、私钥、证书、凭据和 API Key 文件；访问具体敏感文件必须再次确认。

### FR-03 文件变更

- 工具至少支持创建、完整写入、局部补丁、重命名和删除。
- 写前验证目标仍与规划时版本一致，避免覆盖用户在任务期间的外部修改。
- 新建文件重名时才可自动改名；明确修订同一/当前/上次文件时必须覆盖原路径。
- 所有工具结果必须读回或重新检查，禁止只根据模型声明判定成功。

### FR-04 终端命令

- 在授权目录中执行非交互命令，实时流式展示 stdout/stderr、退出码与耗时。
- 读取类和只读联网命令可自动执行；上传、POST、写入、删除、安装依赖、Git 提交/推送等状态变更命令进入任务级审批。
- 命令必须声明工作目录和预计影响路径；访问未授权路径时暂停请求权限。
- V1 不接管密码、登录、验证码和交互菜单；遇到时暂停并给出外部终端操作说明。
- 缺少工具时，面板展示用途、官方来源、安装命令和影响；用户确认后 App 可辅助安装，无法安全自动安装时只提供官方指引。
- 安装若需要写授权根之外的系统目录或缓存，必须在同一确认中列出；该次确认不自动把系统目录加入永久文件夹授权。

### FR-05 调度、并发与冲突

- 全局最大并行任务数为 2，同一会话最大运行数为 1。
- 同一文件或目录存在写冲突时，后来的任务必须等待。
- 读操作可并行；写目录锁和命令影响目录锁必须使用规范化路径。
- 用户离开聊天页、切换会话或隐藏执行面板后任务继续运行。

### FR-06 上下文与持久化

- 工作消息、任务检查点、角色交接摘要、文件路径、工具结果摘要和执行日志跨 App 重启保留。
- 大上下文可压缩，但摘要必须保留：用户目标、未决问题、原始产物路径、已批准范围、已执行副作用、验证证据和失败原因。
- 日志与快照保留 30 天；到期自动清理。
- 快照默认总上限 2 GB，可在设置中调整；超限优先删除最旧已完成任务的快照。

### FR-07 搜索与浏览

搜索优先级固定为：

1. 已配置且健康的搜索 API 或模型原生搜索。
2. 无 Key 的后台网页搜索。
3. App 内可见浏览器搜索并提取公开网页正文。
4. 仍失败则明确告知用户。

其他规则：

- 只访问公开网页；登录、验证码和付费墙必须暂停交给用户。
- 执行日志记录查询、访问 URL、时间、来源和失败原因。
- 默认最终答复不附来源链接；用户追问时再展示日志中的链接。
- 网页内容始终是不可信数据，不能覆盖系统、权限或用户指令。

### FR-08 设置

新增“工作模式权限”设置区：

- 已授权文件夹列表、添加、移除、重新授权。
- “普通写入前确认”开关；不影响始终确认的高风险操作。
- 日志/快照保留天数和快照空间上限。
- 当前快照占用、清理按钮。
- Windows WebView2 可用性状态及缺失时的安装入口。

### FR-09 普通聊天隔离

- 普通聊天、自动聊天、主动私聊不得进入工作任务调度器或调用本地工具。
- 工作模式状态、面板和任务失败不得改变普通聊天的流式回复与消息存储语义。

## 6. 非功能要求

- 单 App：核心 Agent 不依赖外置 CLI、守护进程、数据库、容器或本地 HTTP 服务。
- 云端依赖：AI 推理继续使用每个角色自己的现有 API 配置。
- 模型兼容：DeepSeek、通义、智谱、Moonshot、百度和自定义 OpenAI-compatible 配置都必须有工作模式兼容路径；无法可靠执行时给出具体错误，不能静默降级为普通聊天。
- 安全：路径、敏感文件、外部网页、命令影响范围均在工具边界重新校验，不能只信模型输出。
- 可恢复：任何已发生副作用的失败都必须展示差异和撤销入口。
- 性能：大型目录按需列举/搜索；所有 IO、文档解析和快照操作不得阻塞 Flutter UI isolate。
- 可读性：新文件不超过约 500 行，复杂函数约 50 行内；Agent 主循环、权限、工具、UI 和持久化必须解耦。
- 可观测：每个步骤有开始、成功、失败、等待或跳过终态，禁止“长时间无反馈”。
- 隐私：不在普通日志中保存 API Key、文件全文、模型完整提示词或敏感命令输出。

## 7. 明确非目标与限制

- V1 不做 OS 级强沙箱；应用级限制不能抵御恶意子进程绕过，UI 必须明确说明。
- V1 不支持 App 完全退出后的后台运行或自动恢复。
- V1 不接管交互式终端密码/登录；列为后续优化项。
- V1 不建立大型目录的持久语义索引。
- V1 不处理音频、视频理解。
- V1 不提供 PDF、DOCX、XLSX 或图片内部编辑/生成。
- 本轮只在 macOS 做真实 UI 验收；Windows 完成代码与自动化校验，但在获得 Windows 环境前不得宣称真实 UI 已验收。
- 未来若改为 Mac App Store 沙箱分发，必须另做 security-scoped bookmark 与 entitlement 方案，不属于本地安装包首版。

## 8. 验收总门禁

所有阶段都必须满足：

- 新增逻辑有单元测试或集成测试；关键 UI 有 widget 测试。
- `flutter analyze` 无问题，相关测试与全量 `flutter test` 通过。
- 涉及 Hive 字段时执行代码生成并验证冷启动。
- 每个用户可见失败路径都有可操作提示，不以异常文本或空消息收尾。
- macOS 最终使用真实 App 做逐项操作验收，可使用 computer-use；不能用测试替代真实交互。
- 测试/构建只有在验收步骤明确要求时运行；Agent 日常代码任务默认只做轻量检查。
- 未实际验证的能力必须列为未检查项，不得用“测试通过”代替验收通过。

详细技术方案、阶段拆分与逐项测试矩阵见 `docs/work_mode_agent_v1_technical_design.md`。
