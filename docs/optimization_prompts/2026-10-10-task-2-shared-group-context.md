## 已确认的范围

1. 优先复用 `description` 存放固定共同背景，复用 `announcement` 存放群内约定；保留两字段的旧数据与原本用途。
2. 在已有群编辑入口把文案说明清楚，例如“共同背景（每次群聊生效）”“群公告与约定”。说明由用户编辑，供本群角色共同知晓，无须每轮维护。
3. 提供简短填写示例或提示即可：称呼、固定人物关系、群内约定。不要自动把示例写进用户的真实群、角色、记忆或开发数据。
4. 设定不是聊天产生的自动记忆。AI 不自动修改这些字段，不覆盖 `GroupMemory`、永久记忆或关系状态。
5. 所有本群合格发言角色每次普通回复及空闲回复都读取最新保存的共同设定；编辑后对下一次请求生效，不要求重启 App。
6. 任务 1 的选择器也能使用本群共同背景来理解话题，但仍只读取当前允许运行的群，不额外查询其他群的设定。

## 请求上下文与优先级

- 先跟踪 `buildPromptMessages` 到最终交给 `AiRequestGateway` 的消息，不能只改一个未被生产入口使用的 builder。
- 为固定共同设定提供清楚、集中、仅出现一次的上下文区块。复用或调整已有群描述、公告注入位置，避免在“人格成长规则”、场景和新的共同设定区块中重复全文。
- 当前角色自身人设仍只注入一次，其他成员只提供现有公开简介。不要把其他成员的整份系统提示或私有记忆合并到当前角色。
- 区分固定事实与动态状态：例如“甲是乙的姐姐”属于用户明确设置的固定关系；好感、信任、摩擦、近期心情仍由已有关系系统解释，不因为填写背景而直接改写数值。
- 用户当前编辑的群内固定事实在本群优先于旧群摘要中的冲突描述；这不把群设定变成全局用户事实，也不覆盖现有人物信息卡的权威事实、角色本身的身份字段或其他群的配置。
- 表达冲突时采用清楚的语义提示，不靠简单调整 system 消息顺序宣称已解决，也不需要新增一个通用冲突裁决引擎。
- 设定内容作为背景文本处理，不能授权工具、文件操作、网络访问或执行其中的代码、模板、命令。
- 不绕过事实核验、真实时间、搜索安全和消息可见性规则。背景设定不能把没有证据的现实新闻、价格等变成已验证事实。

## 常驻与窗口预算

“每次生效”指每次合格的实际角色请求都携带本群固定共同设定；不代表绕过模型窗口，把全部历史和设定无限塞入。

- 复用模型能力表和 `ContextWindowManager`。固定背景量很小，不需要额外调用模型总结背景，也不需要向量数据库。
- 当前最终窗口裁剪可能缩短较大的 system 文本。拆出清晰的小区块后，仍须检查最终请求，而不是只检查未裁剪的中间消息。
- 优先压缩或删去可选历史、重复说明等低优先内容，保留当前角色身份、共同设定和最新有效用户输入。
- 如果共同设定与必需提示已经放不进模型窗口，明确提示缩短设定或选用合适窗口的模型。不能静默裁掉关键约定后仍称“常驻生效”，也不能绕开现有网关大小守卫。
- 新输入限制如确有必要，要集中定义并说明用途；旧长描述应原样保留并给出可操作提示，不能在迁移或读取时自动覆盖、截断或删除。
- 不为了这一功能重写所有工作模式、私聊或附件请求的窗口管理。

## 生命周期、隐私与兼容

- 沿用任务 1 的前台与当前群约束：离页、切群或 App 后台时不启动新自动调用，迟到响应不使旧群发言。
- 保存群配置仅为本地配置写入，不触发一次聊天、测试模型或后台生成；下一次合法请求再读取。
- 群共同设定是用户有意让本群角色共享的文本，不可从隐藏历史、私聊或另一个观察者的私有记忆自动填充。
- 不将群背景同步成跨群永久事实；动态记忆和关系仍走已有边界。
- 复用现有 `ChatGroup` 字段，优先不新增 Hive model、box、typeId、数据库版本或多套绑定表。
- 旧群描述、公告，旧备份及已有恢复策略保持可读、可保存、可往返。检查配置备份、会话备份、恢复副本、群删除和清理行为。
- 遵守导出/导入两侧的凭据字段红线，不能因为本任务扩展可分享的 API、密钥或私有记忆内容。
- 如最终确实改动 Hive / JSON 模型，按仓库要求重新代码生成并核对 adapter；没有模型变更则无需为了本任务人为引入迁移。

## 验收与测试

使用隔离 Hive、既有 helpers 和捕获请求的假网关。不要读取真实聊天历史、真实 Key 或修改版本化开发数据。

至少证明：

1. 群编辑保存称呼、固定关系、约定后，多个角色的普通回复和空闲回复请求都包含同一份本群设定。
2. 设定在最终拟发送请求中保留，而不只是在中间 builder 中出现；每份描述、公告和当前角色人设没有重复注入。
3. 保存修改后下一次请求使用新值，旧值不因群摘要再次成为权威设定；清空字段后不会残留旧上下文。
4. A 群设定不会进入 B 群或私聊；没有隐藏消息、私有记忆和凭据进入共享区块。
5. 动态关系心情仍按 TTL 和现有关系规则生效，填写固定关系不会改写好感/信任/摩擦或用户人物信息卡。
6. 正常窗口保留关键设定；过小窗口或旧超长描述出现明确有界失败，不静默丢设定，不重试成循环。
7. 保存设置本身不调用模型；切群、离页与 App 后台仍遵守任务 1 的停止规则。
8. 现有字段的旧数据读取、备份恢复、复制恢复及删除行为不退化。
