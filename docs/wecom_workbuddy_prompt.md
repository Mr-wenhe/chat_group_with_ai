## 二、项目背景（必读，已为你整理好关键事实）

chat_group 是一个 **AI 群聊模拟器** Flutter 应用，工程根目录即仓库根。

**核心数据模型与流程**
- 用户创建多个 **AI 角色（AICharacter）**：系统提示词、头像、回复频率限制、长期记忆摘要。
- 角色编入 **群（ChatGroup）**；消息归属群。
- 用户可与单角色 **私聊（Direct Chat）**，用 `dm:{characterId}` 作为消息 groupId。
- 每个角色绑定一个 **ApiConfig**（LLM provider：DeepSeek / 通义 / 智谱 / Kimi / 文心 / 自定义 OpenAI 兼容端点）。
- 已有 **显式工作模式**：按会话开启后，角色通过 `AgentRuntime` 多步执行本地文件生成、技能创建/下载、工作区/浏览器工具，带 12 步预算与单次 120s 超时；普通聊天和自动发言不进入工具链，敏感工具逐次审批。
- 技术栈：Riverpod（注解式代码生成）+ Hive（本地 NoSQL）+ Dio（网络）+ json_serializable。

**关键技术约束（改动前必须知道，否则必炸）**
- Flutter 为 **3.24 自定义 fork（旧主题 API：CardTheme/DialogTheme），不可切换通道**。CI 已钉到 `flutter-version: "3.24.0"` 对齐本地。
- **`pubspec.lock` 不纳入版本控制**（fork 解析的 lock 含 SDK 专属条目，CI 复用会失败），各端自行 `flutter pub get` 重新解析。
- **`dependency_overrides` 已锁定避免 3.27+ API 编译失败**：`file_picker`（≥8.0.0 <9.0.0）、`package_info_plus`（≥8.0.0 <9.0.0）、`wakelock_plus`（≥1.0.0 <1.4.0）。新增依赖前验证其 Android `build.gradle` 是否用了 `android.flutter` 属性。
- 既有审美约束：**聊天气泡不加描边边框**（用纯色/渐变区分，强调用背景色 + 阴影，而非边框）。
- macOS App **已关闭沙盒**（entitlements `app-sandbox=false`），因为 Agentic 桥接需在进程内 `bind` 端口读写用户文件；发布走 GitHub Release 而非 App Store。
- 代码生成：`dart run build_runner build` 生成所有 `.g.dart`（改 model/HiveType/Riverpod provider 后必跑）。

**常用命令**
```bash

flutter test                    # 须全绿
flutter test test/widget_test.dart
dart run build_runner build     # 改 model/provider 后
# 构建
flutter build apk / flutter build ios --release --no-codesign
flutter build macos --release
flutter build windows
flutter build web               # Web 此前已启用；release 会跑 flutter create . --platforms web
flutter run -d chrome           # Web 走查
flutter run -d macos            # 桌面走查
```

## 五、WorkBuddy 工作模式规范（AI 角色对齐基准）

角色回复与行为应满足：
- **意图优先**：先判断用户是要"闲聊"还是"交办任务"。任务类（生成文件/写文档/代码审查/搜索/总结）走 AgentRuntime 工具链。
- **结构化输出**：用分点 / 表格 / 步骤呈现；长内容先给结论再给细节。
- **先诊断后方案**：信息不足时反问关键问题，而不是直接瞎做。
- **可交付物导向**：任务结果以文件 / 代码片段 / 清单形式回传会话，而非空谈。
- **自检**：交付前自查是否完成、是否有错、是否缺依赖。
- **简洁直接**：少客套，多行动。
