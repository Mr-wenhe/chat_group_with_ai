## 实际实现

### 团队和角色

- WorkRoleRouter.selectTeam 从当前群按有效能力选相关团队；真实软件开发需要开发/测试责任，软件需求文档按文档交付处理。关键词 HTML、游戏、测试不单独触发开发；同一请求明确要求文档和软件时保留双重意图。v1 infer 路径保持兼容。
- 每次发言使用该成员自己的 AICharacter、角色要求、技能、绑定 ApiConfig、凭据解析与治理请求。协调职责由团队成员兼任，不由单一模型生成全体发言。
- 指定成员资格、重名、缺配置、掉线、删除完整收集并给出可处理原因。v2 不回退到别人的同型号配置；失联保留原责任与异议。
- 缺人仅从已有角色库推荐有资格且模型可用的候选，通过 P3 决策确认后加入当前任务，不永久修改群成员。未确认不调用候选模型。

### 自然表达和生产提示

- AgentPromptBuilder.replyGuidance 接入实际 buildAgentDecisionPrompt、v2 成员生产请求以及原讨论模型输入，覆盖 4.1.1：普通回复一至三个短句、接住具体问题、给新增信息；允许追问、反对、不确定和更正；协调者仅收敛/决策/交接时总结。必要复杂解释不强行缩短。
- 公开发布移除统一“职责意见”前缀、合同 JSON 正文、理解百分比及长报告拼接。v1 内部百分比只为旧状态兼容保留，v2 不读取它作为门槛。
- 严格 v2 协议与公开文字分离：全部问题、方案、验收、调查和逐人成员认可都有结构化字段。只有合法协议推动状态，失败预览不能变为认可；有限一次结构修复，没有逐条第二模型润色、无限风格重试、机械拆泡或截前 N 字。
- 移除旧提示中的特定项目样例和强制职业报告冲突；dossier 仅导航项目路径，不扫描/猜测源码事实。
- 完整方案与调查来源/结果以既有消息 MediaAttachment 附带 JSON 详情，存入原事件存储管理目录，真实文件可打开。群工作面板默认可展开全部问题、处置、证据、方案/工作项/验收，不只显示第一项。

### 真实调查和只读限制

- WorkDiscussionRunner 只选择一次调查动作；DefaultWorkTaskRunner.investigate 使用现有 workspace/grant/path/disclosure/sensitive 核查、工具注册与 WorkAgentLoop.investigate 执行。没有第二工具循环、第二执行引擎或临时记忆系统。
- 调查绑定 task/conversation/member/issue/requestRevision/teamRevision；执行前后核对版本、取消和待纳入输入。真实结果先写事件凭据，再更新问题 evidenceRef，然后返回当前调查成员继续讨论。
- WorkToolRegistry 在 ready 前执行严格阶段白名单：受控 list/read/search/document 且定义 readOnly。即使伪装为 readOnly 的 command.run 或 workspace.patch 也被拒绝；安装、写探针与浏览器不变成只读能力，原角色/任务/目录授权继续生效。
- 读取文本、代码与文档复用原入口。授权图片复用 WorkAgentLoop 原生多模态组装/图片数据剥离逻辑，真实图片内容进入当前调查成员的原生消息与治理能力检查，不把 base64 包进 JSON 文本；详情只保留来源和图片传递标记。
- P2 识别 document 的真实读取进展；重复签字、重复提案、空回复、模型自报进展不重置停滞保护。
- 外部搜索只消费当前请求、当前群与成员可见、上下文分界线之后的已有 WebSearchSnapshot，继续使用原 SearchContextFormatter 安全证据。未新增查询工具或绕过搜索策略/gateway；浏览器默认边界不变。

### 状态流与交接

显式 v2 任务 → 相关团队与资格核对 → 当前问题选择发言者 → 受控调查/自然回应 → 真实证据处置问题 → 协调成员建立完整方案/合同/工作项/验收 → 当前团队每人对当前版本明确认可 → ready。

未知玩法、真实分歧、成员缺口和停滞进入 P3。用户答复按安全点纳入并恢复讨论；成员恢复后重新检查资格和团队版本。异步失败保留诊断并要求恢复，避免自动无限重启。

新范围保存完整不可变提案；全员对同版本明确同意才更新 scope/需求/计划/验收，旧版计划认可失效。有反对保留原始意见，交 P3 拒绝、修改或用户明确采用原提案；用户裁决不伪装成反对者签字，仍需对更新方案逐人成员确认。原范围不得被删除，确定性的直接禁止冲突不能自动采用，工具授权永远不由提案扩大。复杂语义的禁止识别仍依赖成员核查和用户裁决，不声称字面规则可覆盖任意自然语言。

v2 不使用 min/maxRounds 或 96 次总调用限制；有效进展超过六轮或 97 次真实读取继续推进。请求/工具超时、协议有限修复、上下文和体积边界保留；必要上下文超窗明确求助，不截掉问题与认可。

P5 接入点为真实成员角色/技能与现有 task.contextSummary、WorkContextBuilder.discussionState，未另造角色记忆。P7 接入当前完整 plan/artifactContract/workItems/acceptances 和版本。P4 ready 表示方案可交接，isExecutionReady 对 v2 仍为 false，未假装制作、测试、复测或最终交付已经完成。

## 发现与修复

按影响排序，校验过程中发现并修复：

1. 调查完成后 next_member 可能覆盖调查者回答、成员恢复可用标记不更新、P3 答复不恢复讨论；现保持调查发言权、更新团队版本并在安全点继续。
2. v2 曾沿用同型号 API 配置兜底，生产网关实际返回 message，图片结果曾仅进入 JSON；现精确成员配置、解析真实返回形状并共用原生多模态组装。
3. 新范围/团队或需求变化可能保留旧认可，重复认可可能伪造进展；现版本失效与 P2 重复保护，用户采用保留原异议。
4. dossier 猜测项目事实、公开合同/百分比/报告模板和详情入口不足；现只导航、自然公开文本、完整可达详情与全部问题 UI。
5. 文档意图判断曾影响 v1 router，旧端到端断言依赖公开百分比，FIFO 测试依赖固定等待时间；现限制新路由到 v2、更新实际自然发言断言、等待真实启动计数。
6. 图片新增测试初次失败因测试使用不存在的 provider 和不合法 issue.kind，修正为实际 qwen-vl-max/decision 后验证真实 document 接线通过，未放宽生产协议。

质量清单：权限与边界验证、明确命名/版本、复用原事件/文件/角色机制、有限状态与上下文容量、取消/迟到结果保护和 v1 兼容均已审查。新业务 parts 各小于 500 行，未改 Hive/JsonSerializable 字段或 generated 文件；已有较大文件未借机重构。讨论调度、响应采纳、请求生命周期、协议修复与提示组装分开，按约 50 行和单一职责复核；声明性协议/提示字段保持完整，未为缩短文件删门槛信息或新造框架。
