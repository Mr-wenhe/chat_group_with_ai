## 实现

- 决策保存在 P1 的 `WorkCollaborationState.decisions`：任务身份、决策 ID／修订、原因、依据、选项与各自影响、总体影响、目标事项、答案、仍缺条件及提醒状态。`WorkTaskDecision.forTask` 从同一权威状态投影给 `WorkTaskClarification.isAnswerable`、聊天提醒、面板与弹窗；v2 不再由空的 v1 执行人字段误发“补成员”提醒。旧 follow-up 目标选项、拒绝答复提示和清理逻辑继续使用原入口。
- 协调器的 `respondToDecision` 在串行事务中校验任务、决策修订与动作，再更新检查点；选项、自由建议、指定项暂缓、明确豁免和人工验收按目标区分。未解决的答复保留 pending 与具体缺口。裸“先继续”不会变成通过或豁免；没有明确目标时拒绝暂缓。人工结果标为 `manual`，引用用户消息或决策答复，不冒充自动测试结果。决策变化使旧团队认可失效；命令审批仍走独立版本化审批入口。
- 暂缓项保留 `deferred`，独立工作项可继续。其余可完成工作项结束时，投影给出 `remainderReady`；初次提醒与收尾提醒分别持久标记。前台对应会话自动弹一次，多项在同一弹窗中逐项显示；关闭弹窗不答复，面板按钮可重开。其他会话不会抢焦点。缺成员的候选由决策选项显示并由用户选择，不修改永久群成员；P4 负责从角色库产生真实候选与资格核验。
- `enqueueFollowUp` 在用户消息已落库后，把补充原文、消息 ID 和对应附件消息 ID 同步写进任务检查点；运行中在 `WorkAgentLoop` 模型结果后、工具前及动作完成后的安全点停止旧版本，协调器依 FIFO 纳入新版需求。已经发生的工具副作用由既有检查点保留；晚到的旧版结果不覆盖新版本。完成前在协调器串行收尾中再次核对待处理输入。明确独立新任务仍由原 FIFO 提交，进度询问不修改需求。删除或终态任务的迟到答复不能复活记录。

## P4/P7 消费接口

P4 通过 `WorkCollaborationUpdate` 写入真实问题、选项、目标工作项和成员候选，使用 `WorkTaskDecision.forTask` 暴露统一待答状态，并核验选人资格。P7 的调度从 `decisions` 读取 `deferred` 目标及 `workItems.dependencies`，只派发无依赖的已确认工作；完成工作项后更新 `workItems.status` 以触发 `remainderReady`。真实执行 runner 在安全点消费 `pendingInputIds`，重新讨论受影响部分并重做失效的验收；最终交付必须满足 `collaboration.deliveryReady` 且输入队列为空。P8 在启用前补真实导航、重启、竞态和收费边界以外的端到端验收。
