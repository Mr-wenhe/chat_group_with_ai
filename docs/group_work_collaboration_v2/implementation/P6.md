# P6 — 候选交付版本、证据文件与可靠重发

日期：2026-10-01。仅 P6。保留开始时已有的 P1–P5 及其他暂存/未暂存修改；未提交、推送、默认启用生产群 v2，也未实施 P7 调度或 P8 跨设备验证。先阅读 CLAUDE.md、设计、证据计划及 P1–P5，复用现有文件授权、delivery guard、附件筛选/打包/copyToMedia、媒体仓库和备份通道，没有新增 Git 服务或第二套仓储。

## 生产边界与文件位置

`DefaultWorkTaskRunner.publishCandidate` → 既有 `WorkArtifactDeliveryGuard.validateTask` → `_safeArtifactsForAttachment` → `WorkCandidatePublisher.publish` → 协作状态 iterations 检查点 → `sendCandidateVersion`。消息首次送测即附真实冻结文件；制作成功只产生候选，不能把旧 single artifact 自动完成当成整项验收成功。

公开 P6 接口由受控 runner 集成测试真实调用。旧 v2 执行门禁仍保留，P7 负责选择工作项、提供明确软件文件合同、调用制作/审查接口并消费 `workItemCompleted` 信号。新增状态不是根任务 `completed`；v2 的自动单文件完成捷径被关闭，显式 finish/handoff 提供工作项完成信号，根任务暂停等待后续调度。没有宣称群制作到最终交付已经自动闭环。

用户工作文件继续由既有 workspace mutation/path policy 在原授权路径修订。同名修订钉定仍只用于目标交付物，脚本、素材和分段源文件按自身路径写入。候选副本单独放在现有媒体目录 `work-deliveries/<taskId>/rNNN/artifacts/<真实相对路径>`，不更改用户输出位置或自动重命名原文件。

`candidate.json` 固定 schema、发布标识、iteration、任务/群、需求版本、团队版本、制作者、团队身份、合同类型/格式、便携重建基线、文件相对路径/尺寸/SHA-256 与整体 `artifactDigest`。内存 manifest 也递归不可变。原工作文件修订不影响旧副本；同基线内容没有变化不能制造新修复版本。编号同时参考已发布目录及任务已有 iterations，不因部分文件清理复用历史编号。

软件必须显式给出完整合同清单；缺少必要交付物、筛选跳过任何合同文件或包体不足都失败。软件始终按真实相对目录打包，HTML 本地 src/href 必须能在包内解析；DOCX 继续复用真实 ZIP/XML/正文检查，HTML 必须有有效结构及非空正文。旧文件的 freshness/变更证据仍由既有 guard 校验。声明清单是软件合同边界，不能用散落差异文件冒充完整游戏；非 HTML 软件的构建与运行验收仍需本轮工具/人工证据，P6 不把静态清单核对冒充运行测试。

过滤凭据、密钥文件、环境文件及无关构建/依赖缓存；常见文本和 DOCX 正文复用敏感信息扫描。不递归打包整个授权目录。单文件 50 MiB、候选 200 MiB、64 个合同文件、单任务保留额度 1 GiB、单元数据 1 MiB；空间或复制错误明确失败，不静默删历史、缩减合同或覆盖版本。额度检查是保守应用限制，实际磁盘不足由文件系统错误处理。

## 文件与 metadata 的原子边界及恢复

1. `pending.json` 通过临时文件 flush/rename 记录发布身份与保留编号。同一 publicationId 的重试使用同一编号和基线。
2. 在同一媒体文件系统的 `.rNNN.staging` 中复制合同文件，逐个核对尺寸、复制前后源与副本 SHA-256、结构及引用完整性，再写 `candidate.json`。
3. 校验完成后目录 rename 为 `rNNN` 是候选内容提交边界。缺文件、复制中断、源文件变化及磁盘错误不会生成可返回的完整候选。
4. `index.json` 通过临时文件 flush/rename 更新，是可重建目录索引。发布后索引写入失败，完整目录保留；`recover()` 校验每个真实目录并重建索引，清掉对应 reservation。重复恢复、重复 publicationId 不新增版本。
5. Hive 协作 iterations 检查点与文件 rename **不是跨存储事务**。目录提交后、Hive 更新前崩溃，重试相同 publicationId 可找回目录并补登记；仍核对需求/团队/状态版本，不能直接采纳失配候选。消息 metadata 与附件复制也不是事务：先保存稳定消息身份和文件引用，再逐个复制/核验附件，失败保留独立投递 notice。

目录 rename 和 metadata rename 保证同文件系统的原子可见性；未承诺操作系统突然断电后的目录 fsync 持久性。应用内串行锁只协调当前进程，未增加多进程共享媒体写入功能。`recover()` 拒绝损坏历史，要求明确处理损坏/清理；不能把损坏候选继续标为完整。`discardUnpublished` 仅显式放弃未提交 reservation/staging，不能删除已发布候选或用户文件。

## 审查、签字和封存

`beginReview` 校验真实候选及可选被测工作区，记录 actor、attempt、验证版本；软件制作者不能兼任独立测试角色。每个 attempt 有独立 `start.json` 和 `report.json`，不覆盖前一次报告。记录方法、工具/人工来源、receipt、验收项和结论；人工报告不能自称工具自动通过。

`review:rNNN:<attempt>:<报告SHA-256>` 绑定真实报告内容；报告又绑定候选 `artifactDigest`、需求/团队/验证版本。开始和结束测试都校验文件，被测工作区后续外部变化也使旧证据失效。本机测试文件映射保存在 `workspace.json`，不备份、不恢复授权。候选文件、manifest、文件集合或报告被外改，旧证据失效，原报告仍保留。

`sealOutcome` 仅在本轮验收结论齐全、版本对应且真实报告有效时写独立 `outcome.json`；成功交付还需现有全员版本认可门槛。人工/豁免必须有用户 decision 凭据。outcome 一次封存，相同封存重试幂等，不把签字内容塞回不断变化的 candidate manifest；封存后禁止新审查或覆盖结论。

## 消息、重发与数据生命周期

消息区区分“候选送测”“本轮审查报告”“正式交付”。`Message` 追加可空 Hive field 16 `workDelivery`，旧消息兼容；含稳定版本身份、原发送者、真实文件引用及摘要。稳定消息 ID 基于 task/iteration/kind/evidence，投递失败不改变验收结论。

`resendCandidateMessage` 从持久消息和目录索引恢复原冻结文件。queued 投递重试分支不调用模型、制作工具或当前成员凭据；换执行角色仍保持原制作者/报告作者。已复制且摘要一致的附件复用。最终版本重发核对原封存文件及 outcome 摘要，不要求后来任务再次收集签字；任何原封存内容变化均拒绝。首次正式交付仍须完整验收和签字。

回滚快照仍由 `WorkSnapshotService/Manifest` 撤销与原清理策略管理；候选在媒体目录，快照清理不会删除交付副本。任务真删除保留用户工作文件及消息已生成文件，不能通过重试复活任务。明确删除消息/附件走现有 `DataLifecycleService` 与 `ManagedMediaStore`：嵌套引用纳入使用量、附件清理及孤儿清理。消息存在时保护对应候选目录后续追加的报告；最后引用删除后清理版本和相关文件。task-level index 是可重建缓存，孤儿清理可移除，不能用于恢复可执行任务。

## 备份与导入

完整/会话备份通过原附件通道收集冻结文件、manifest、attempt 报告和 outcome，逐个核验尺寸/摘要并按内容去重。嵌套 `files` 明确声明便携相对引用，过滤本机绝对路径、权限、workspace 测试映射及临时文件。缺附件列为明确缺失；摘要被改拒绝导出。附件里的 JSON 是附件内容，不再被误当数据库 JSON 记录校验。

便携 metadata 仅白名单身份、版本、kind、evidenceRef 和附件路径/尺寸/摘要；配置备份不带消息或交付历史。导入重映射消息 envelope 的新任务/群/成员 ID，但冻结 manifest/report/outcome 内的历史 ID 保持原字节，避免篡改摘要；它们是历史证据，不能沿旧 ID 恢复权限或执行。所有导入 envelope `verified=false`，不能直接可靠重发或签字；跨设备重新核验及最终验证留 P8。没有搬运旧机器目录授权。
