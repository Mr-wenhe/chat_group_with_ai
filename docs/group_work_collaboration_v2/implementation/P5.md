# P5 — 成员人格、心情与可追溯工作记忆

日期：2026-10-01。范围：仅 P5，复用统一人物配置、`MemoryContextSelector`、`PermanentMemory`、`ObservationEntry` 和现有重试队列。未默认启用 v2，未提交或推送，未实现 P6/P7。开始时已有 P1–P4、备份与其他工作模式修改；保留其内容及暂存状态，不将整份工作区 diff 认作 P5 独有改动。未读取 `data/` 中私人对话或凭据，没有调用真实收费模型。

## 生产读取链路

- P4：`work_discussion_v2_session.dart::_request` → `runWithUnifiedMemory` → `MemoryContextSelector.select(forWork: true)` → 当前成员的真实 gateway。讨论与调查前发言共用此入口。
- 既有讨论：`work_discussion_runner_model_io.dart::_buildPrompt` 同样调用统一入口。
- 实际执行适配器：`DefaultWorkTaskRunner._completeModelTurn` 先压入核心目标、协议与工具证据，再按当前 `task.characterId` 调用统一入口，最后发送 gateway。角色变化时拒绝沿用旧角色的模型配置。个人上下文不会写入循环历史、压缩摘要或任务检查点。
- 当前成员使用自己的 `rolePlaySystemPrompt`、职业、`personalityTags`、观察者记忆及可见关系。没有恢复弃用的 `memorySummary` 权威地位，也没有第二套人物/长期记忆服务。
- 关系通过 `effectiveMood()` 读取，过期为 neutral。生产提示限定人格只影响措辞和关注点，历史记忆作为数据，用户要求、事实、权限与验收优先；不自报职业、不编经历、不强塞情绪或生活记忆。
- 个人上下文插在身份 system 之后，以 user 数据消息发送，保留尾部协议与当前输入。记忆预算 800 字、关系预算 400 字；工作模式排除无关键词相关性记录。执行按模型 token 预算、P4 按字符窗口预算排除超限个人上下文，不能为它挤掉当前目标、未决项与证据。

## 项目作用域

`WorkModeWorkspace` 追加可空 `projectScopeId`（Hive field 5）。已有记录缺字段为 null；通过授权的 `loadOrCreate` 首次使用时分配 UUID，重复加载保持。同一会话改变工作目录时轮换；重绑定相同目录保留已有身份；不同群即使目录相同也不共享 scope。不根据路径字符串推断跨群是同一个项目。

P4 启动时实际加载工作区，空协作状态通过受信 `projectBinding` 更新绑定 UUID；已有计划、问题或工作项的任务遇到另一 scope 要求新建任务，不能迁移旧事实。`projectBinding` 仅讨论 runner 内部可用，协调入口不能伪造。循环及模型响应后的检查防止目录变化继续采纳旧项目结果；调查工具入口再次检查实际工作区 scope。

具体项目事实留在当前任务的协作版本、文件和调查证据中。本阶段没有新增跨任务项目历史检索通道，因此不会绕过删除任务推进的 `WorkContextBoundary`。用户明确要求记住的工作规则保留为该 scope、该来源会话的 `projectInstruction`；检索同时检查当前 scope、来源会话和删除分界。无有效 scope 时为 unbound，不能跨项目启用。pinned/明确记忆不能绕过这些条件或主体可见性。

旧无来源事实不能可靠判定项目归属，不猜测迁移：工作检索排除它们，只兼容用户主体的手工稳定偏好。普通群聊/DM 的既有无 scope 记忆行为保留；新增项目专用记忆不会被普通全局 selector 捞回。

## 生产写入与失败恢复

1. 工作用户输入在观察前标记 `Message.isWorkMode`（field 14）；P4、既有讨论及实际执行交付消息也标记。旧聊天观察入口仍调用同一个 `ObservationEntry`。
2. `ObservationEntry.distillMessage` 对工作消息禁止普通 LLM 事实提炼。未验证聊天猜想及仅口头声称的经历不写全局事实。工作中的明确记忆默认项目专用；只有明确要求跨项目/所有项目/全局的稳定偏好才生成 `stablePreference`。
3. P4 实际工具成功、有 receipt 并提交协作状态后，给执行该调查的成员消息追加 `workMemoryEvidence`（field 15）：task、scope、issue、requestRevision、tool、evidenceRef。公开调查附件保留原始来源与结果。
4. 同一 `ObservationEntry` 的 work 扩展先进入持久重试队列，再写该成员自己的 `PermanentMemory.workSource`（field 20）。检查消息实际落库、工作标记、AI 作者自身可见、工具白名单及来源任务仍存在且会话一致；协调者不批量替所有成员写经历。
5. 确定性归纳仅保存真实发生的 `workspace.read/search/list/document` 方法，附固定适用条件、来源 scope/task/message/receipt/revision。示例：“曾实际使用 workspace.read 完成授权材料查证。”不保存模型推断出的项目结论或猜想。跨项目读取时明确标为历史方法，当前项目必须重新验证。
6. 去重身份含 actor/message/receipt；含失效记录的存在检查防止重启回放恢复已遗忘经历，同成员同工具方法还做内容去重。失败保留队列，不改变已成功调查的结果；成功精确清理对应队列及 retry marker。自动记忆关闭时不新增待写队列或记录。重试重新读取落库消息，删除或纠正后不能拿旧对象恢复 receipt。

这里选择有限、可证明的工具方法归纳，不实现任意工作结论的自动语义学习。验证结论仍只在任务版本/证据中，不会把后来推翻的项目结论保留为通用事实。历史确实发生过的读取动作可以保留，但不等价于读取结果通过验收。手工纠正历史方法时降为来源项目的 `projectCorrection`，保留原来源并替代旧记录，不再作为跨项目已验证经验使用。

## 审计、遗忘、备份和兼容

- 所有受影响的永久记忆复制/更新写入者保留 workSource；普通冲突提炼不能跨 scope 自动覆盖工作记录。纠正去重同时比较 scope/type。
- 记忆详情显示工作来源、适用条件和“当前项目仍需验证”，既有 sourceMessageIds 可追溯调查消息及其附件。遗忘保留审计来源；物理删除先清除源消息 receipt，再删记录，旧重试无法复活。
- 继续使用现有生命周期的 observer/subject/originConversation/sourceMessage 删除规则及重试清理，没有新增 box/settings key。
- 备份永久记忆只输出允许的工作来源字段。消息保留 isWorkMode，但不导出可触发可信经验再写入的 workMemoryEvidence；导入不会重放调查记忆。
- copyWithNewIds 恢复重写 observer、participant、来源会话/消息、taskId 及调查 receipt 中的任务前缀；项目专用 scope 与 originScope 变为 portable-unbound。通用方法 scope 仍为 null，保留来源与适用条件；工作区仍按既有规则解绑路径和 scope，需重新授权建立身份。
- 三个 Hive adapter 已生成；旧缺字段分别安全默认 null/false/null。旧 adapter 字段读取测试使用内存 reader，不打开仓库真实 Hive 文件。
