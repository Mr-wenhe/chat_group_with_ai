## 3. 崩溃窗口与收据边界

`work_agent_loop_actions.dart` 在可变操作进入 handler 前先落盘 `mutationRecoveryVersion` 与 `uncertainAction`。完整非 append/非 parts 的覆盖写记录目标和预期 SHA-256；其他操作只记录身份，不能凭模型文字证明已发生/未发生。返回结果后使用现有设备事件 detail 文件存 hash-only 提交收据；提交缓存有界 128 条，持久收据可防止缓存外重放，删除/清除复用已有生命周期。

恢复先检查设备本地已提交收据；若收据前中止，仅完整覆盖写可按当前授权目录内真实文件大小/摘要核对。匹配才记提交并清 uncertain，外部改动/无身份/命令/追加写/安装/删除/外部调用无法证明时暂停求助，不盲重放。返回明确退出码的失败调用属于已发生操作，可消费操作身份，但不因此将验收记通过。持久 uncertain 时禁止有限工具重试把同一副作用再调一次。

故障注入测试实际写临时文件，在工具副作用完成而 receipt 回调前中止，重新读取 pre-crash checkpoint 后不再调用模型/handler。另测 SHA 匹配与不匹配、不可证明 command 释放槽并通知、收据 reopen 与 task 作用域。**不承诺普遍 exactly-once；真实 OS kill、任意第三方工具及所有硬盘断电组合未检查。**

## 4. 备份、ID 与数据生命周期

复用 P6 的完整/会话版本文件和关联报告收集与既有附件 SHA 校验；配置备份不含任务历史。缺物理文件写入 missing/incomplete，外部篡改会拒绝备份，不把索引当可打开文件。`workspace.json` 的本地被测路径映射不导出；提交动作 detail 不进入备份。

`backup_entity_codec_memory.dart` 保持导出/导入双侧白名单清洗，递归清洗公共协作文字；经格式白名单检查的实体 ID/哈希保留原值，不把版本摘要当 opaque token 抹除，合法合同相对文件名按原值检查并保留；绝对位置、工具审批、资源锁和可信本地收据不携带为新设备权限。未知协作状态携带 unsupported/invalid 阻塞标记。补充 `attachmentMessageId`、`sourceTaskId`、`queuedAttachmentMessageIds` 的便携及新 ID 重写，嵌套 task/conversation/character/message、决策成员/来源、认可身份仍经已有 rewrite。项目重新绑定，team/verification 版本变化，导入 `verified=false`；旧认可只作为历史，不能跨新内容/角色放行。

**冻结的历史 artifact/manifest/report 原字节、原始来源 ID 和内容摘要保留；机器活动实体引用重写。** 不将历史 manifest 的原 provenance ID 当新环境执行引用或可信签字。真实第二台设备导入未检查；受控 copyWithNewIds、全量/会话/configuration、报告物理文件及缺失/篡改测试已通过。备份用户产物本身不重新解释为当前工具权限；不是通用文件正文脱敏器。

没有为已有状态新增重复设置键；既有 schema migration marker、folder grant、agent setting、WorkContextBoundary 仍沿 backup keys/conversation scope/ID rewrite/data lifecycle 路径。删除任务保留已生成交付文件，媒体随自身引用和保留策略清理。发现并修复事件存储 `clearAll` 清空整个 tombstone 集合的问题，现在只由 `reconcileDeletionGates` 按确有恢复记录的 ID 解禁；迟到 runner、模型、弹窗、记忆、版本和事件写不能复活不存在的任务。

## 5. 上下文、正文证据与 UI

根 checkpoint/模型上下文保持有界引用，完整细节与版本留在事件/媒体文件；未决项、延期、认可身份不靠截断放行。每类当前记录 64 条、提交动作根缓存 128 条；候选历史单任务 1 GiB、元数据 1 MiB 等既有上限达到时保守阻塞，不宣称无限任务无限留存。

本阶段受控 Word 闭环发现实际缺陷：二进制读取只返回相关片段，无法证明审查读完长正文。复用文档 parser 的 chunk，`workspace.document` 新增 `startChunk` / `nextChunkStart`，每页最多 4 chunks，返回 canonical path、总数和截断标记。专业审查按真实工具页覆盖全部 chunks 才通过，检索片段不能冒充全文；工具前后仍核对 candidate/被测文件，缺页不放行。真实 DOCX 字节生成/解析/分页可验证，测试模型与 Pandoc 进程是受控 fake。

公开报告在候选发布层统一对 method/receipt/report 和便携 baseline 的本地路径/凭据脱敏，覆盖 Unix、Windows 及 UNC；可信原始工具收据仍仅设备保存。任务面板的 v2 显示阶段、待决事项、版本文件、验证与逐成员认可；旧百分比和累计时长继续按钮不用于有效 v2，真实单次失败仍显示。uncertain 操作生成有身份的查看任务通知，不把点击继续当作副作用核对证明。

已局部更新 `CLAUDE.md` 的新群流程、结构校验、handoff、恢复/deadline、备份历史及容量事实，更新 README 用户流程；没有复制 AGENTS 权威约束，也没有覆盖无关说明。

### 开发中失败：一次收集与修复，没有掩盖

1. 新收据路径的 nullable 调用、恢复拆分遗漏类型引用、S8 gateway lambda cascade、extension import 等编译失败：修正后全量编译/测试通过。
2. unknown schema 旧测试预期 normalize 成空状态：改为检查保留原检查点，生产路径阻塞；没有把安全门槛改弱。
3. manual/waiver fixture 将已返回失败退出写成 `exitCode=null`：真实明确失败应用退出码 1；null 保留为 uncertain 负向场景，不能借假夹具允许盲重放。
4. portable contract 空 `files` 与脱敏位置被当合法路径：空字段移除，位置依据原值判断相对安全路径，导入未绑定，不误造可执行路径。
5. 旧 UI/S8 测试仍按 100% v1 协议推进：UI 改验证新群无预签字及独立 DM 原行为；S8 改完整 v2 协议、真实临时文件、独立专业审查，不用 100% 绕过门槛。
6. Word 审查片段≠全文：修实际工具分页/收据完整性，保留缺页阻塞；隔离媒体根和桌面根避免访问用户真实目录。
7. 副作用崩溃测试起初未注册 patch/缺阶段绑定及期望状态不符合 loop 捕获行为：补真实可变 handler，保存 pre-crash checkpoint 再恢复，断言文件已写且重开无重放。
8. 最终备份复查发现相对文件名和 SHA-256 会被泛化文字脱敏误改：在合同路径和已验证机器 ID/摘要字段保留原值，回归断言验证嵌套相对路径、版本摘要及新 ID。公开报告路径清洗收口到发布层，增加跨路径形式断言。
9. 中间全量尚在运行时新增公开报告测试，旧编译 kernel 与新断言不一致，出现公开路径残留1失败；不能视为 flaky 忽略。冻结代码后公开报告专项20项及最后全量2982项通过，实际收口脱敏生效。
10. analyze 的新增 curly 提示、失去调用的 v1 `_s8DiscussionTurn` 与 unused import 已清理；既有 const 提示做无行为修正。最终静态检查零问题。

这些是实施过程中的失败，最终自动结果没有残留测试失败；不将之混同为“真实验收通过”。
