# P2 实施记录：累计预算与停滞保护

日期：2026-09-30。状态：**部分实现，未通过完整 P2 验收；生产 v2 仍未默认启用**。仅处理本阶段，没有提交、推送或开始 P3。

## 前置接口核对与实施边界

开始前已完整阅读仓库 `CLAUDE.md`、本目录 `README.md`、`01-design.md`、`02-evidence-and-plan.md`、`implementation/P1.md`，检查 `git status --short` 和 P1 状态／协调器测试。工作树已有 P1 与其他未提交改动，均保留，没有回退或覆盖。P1 提供 `WorkDiscussionState` v2、`WorkCollaborationState` 及 `applyCollaborationUpdate` 的受控状态入口；它**没有**提供可执行的 v2 讨论／工作项入口：`work_discussion_runner_setup.dart` 遇 v2 直接返回，`WorkDiscussionState.isExecutionReady` 对 v2 为 false，协调器讨论启动亦阻止 v2。因此本阶段不能绕开门槛让旧单执行者 runner 消费新协作状态。

这意味着 P2 可以把预算策略接到现有生产调度／执行边界，并验证隔离与安全性；但尚不能实测一项 v2 群任务连续执行 101+ 动作或完成 97+ 次真实讨论调用。旧 `WorkDiscussionRunner` 的 `minimumRounds`、`maxRounds`、`maxCalls` 仍只管 v1，v2 不能进入；P4 必须在真实 v2 讨论调度中取消这些门槛，并做 V12 的完整复核。此缺口不以调高上限、清零计数、模拟已执行或另造业务状态掩盖。

## 本次改动

- `WorkTaskExecutionPolicy` 只在任务／群身份匹配、v2 讨论状态校验通过、根检查点无需复核且不是 DM 时取消累计限制；未知、损坏、跨任务和 DM 状态保持旧语义。`WorkAgentLoop` 的动作与 60 分钟检查、重试内部检查、传给模型的动作分母、事件 `progressTotal` 和任务面板均按同一策略分流。`DefaultWorkTaskRunner` 仍传入原配置，普通任务上限不变；v2 仍记录累计 `actionCount` 与起始时间，不清零伪装继续。
- 协调器的 120 秒 `autoResumeRoundTimeout` 不再包住已校验 v2 群任务的整段自动续跑；普通任务保持原包络。用户继续 v2 时不重置累计动作／时间。单次模型和命令时限、有限重试、取消、审批等待、并发、费用／速率治理、日志保留仍沿用既有路径。
- `WorkProgressGuard` 是根检查点中的**技术性诊断记录**，不改变 P1 的 `discussionState.collaboration` 业务权威。阈值集中为连续 3 次同指纹／同输入条件失败，或连续 8 个无新证据结果。只用真实工具结果／内容变化证明进展；模型自报 `substantive_progress` 和计划换措辞不算。相同文件输出指纹不会刷新进展；不同、相关的读取结果可以推进调查。最近有效进展、短尝试摘要和仍缺什么有界保存，停滞时暂停并等待后续 P3 决策；审批等待不计无进展。检查点不保存原始工具结果或私有推理，诊断摘要不拼接模型或工具的原始错误文本。已提交但随后报错的工具先记副作用，再判停滞。
- 面板 v2 不显示 `x/100`、旧讨论理解百分比或无限动画分母；旧“一键再讨论两轮”入口只保留给 v1。v2 仅显示真实累计动作数。原用户回复／取消入口不变。

## 验证结果与限制

通过：`flutter analyze --no-pub` 无问题；`git diff --check` 无空白错误；`flutter test --timeout 30s --reporter compact` 的 `work_task_execution_policy_test.dart`、`work_agent_loop_test.dart`、`work_task_budget_wait_test.dart`、`work_discussion_runner_test.dart`、`work_failure_recovery_test.dart`、`work_task_coordinator_test.dart`、`work_prompt_context_compactor_test.dart`、`work_task_panel_test.dart` 合计 402 例通过。测试没有收费模型调用，也没有真实等待一小时。受控策略测试覆盖 101 累计动作原值、跨 96 分钟的 97 个不同读取证据、重复失败／重复话术、审批等待和新条件下恢复；现有回归覆盖 v1／DM 预算、单次超时与重试、取消、讨论旧语义、上下文压缩和 widget 计时器。

未通过完整验收：V11／V12 的 v2 真正可执行跨额测试、V16 的 v2 自动恢复超过 120 秒真跑测试，因为 P1 的执行门槛阻止创建这条生产调用链。V13／V14 的 guard 核心规则通过受控结果测试，但尚不能宣称在 v2 实际成员讨论与工作项中端到端生效。V15、V43、V48 仅由既有保护和相关回归覆盖，没有在新的 v2 执行链重新证明。讨论中无固定最低／最高轮次及调度让权后的自动续调仍待 P4 接线与复核，不能把现有 v1 runner 当成已迁移。费用外部约束保持原实现，未进行收费压力测试。

质量自检：已检查状态身份、损坏检查点、持久副作用次序、失败／审批边界、敏感诊断、上下文有界性、DM 兼容、面板分母与死循环风险；没有新增依赖、Hive 字段、第二执行引擎或用户可见实验开关。P4／P7 接入真实 v2 执行时，必须让本策略进入对应 runner 并补上述未通过验收，不能将本记录当作 P2 已全部完成的证明。
