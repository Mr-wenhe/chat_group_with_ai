# 实施与角色运行提示词

日期：2026-10-13。用途：将已确认设计交给编码代理实施，并为接通后的角色提供运行提示词。

这些文本包含已确认规格和运行示例；提示词本身不会注册能力。v2 自主裁决、逐成员使用合同和受控 `native.app` 入口已接入代码，但不代表 macOS 现场验收通过；能力仍由当前 production registry、候选、权限、依赖和系统状态决定。运行提示中的 `{{...}}` 必须由可信应用上下文替换；当前解析器不支持的工具/字段不得直接发送。

## 1. 开发总提示词

```text
你在 Flutter 仓库 chat_group 工作。完整阅读根目录 CLAUDE.md，再阅读
docs/autonomous_group_work/01-research.md、02-design.md 和本文件。
这些需求已与用户确认，不重新开展需求访谈。面向用户使用中文。

目标：在现有群工作 v2 中完成自主协作闭环：
真实成员讨论 -> 协调者定案 -> 一位执行者制作 -> 冻结文件候选 ->
所有参与成员各自实际使用不同场景 -> 真实反馈 -> 修复和复测 -> 达标交付。
优先 macOS .app，并完成文档视觉/文字检查和群聊/私聊共享 GitHub 技能。
保留人格、关系和统一记忆，公开群聊自然接话，不写台账式报告。

先核对工作区实际代码和 git diff，保护用户已有改动。
使用 rg 找出每项变更的调用方、解析器、权限、持久化、备份、UI、测试和配置。
先做 P0 的 macOS 现场可行性验证；未验证原生路线前，不重写协作架构。
P0 至 P5 按依赖串行实施，完成上一阶段可执行检查后进入下一阶段。
只实现本次范围，复用现有协调器、单一 WorkAgentLoop、Dio、文件服务、
候选发布、事件存储、模型网关、进展保护和任务面板。
不增加第二执行循环，不提前实现多人并行、手机/Windows 远程平台或插件市场。

单制作执行者与试用角色的 actorId 分开；切换试用者不改用户钉定 executorId。
每个成员必须用自己的模型做操作决定和反馈，有自己的场景与工具收据。
模型不能给自己生成有效 receipt、代签、伪造测试、通过标签或人物资格。
完成门禁核验当前候选、必达项、复测、全员使用、未处理输入及真实交付文件。
一份 tests JSON、退出码 0、截图文件存在都不是完整使用证明。

协调者可裁决授权范围内实现和偏好分歧，必须保留真实反对意见和理由。
同步修改状态和门禁，不能只改提示词。实质验收失败不允许裁决为通过。
改变用户明示目标、权限越界、缺必要环境、自动调整仍无法推进时才询问用户。
授权目录内普通修改、构建、启动被测产物、使用和写证据可连续执行。
系统级安装、发布和超出授权的访问仍要走已有明确授权入口。

用户不设任务费用、时长和迭代预算。不要新增累计轮次上限。
复用单次时限、有限网络重试和 WorkProgressGuard，显示真实累计用量。
空转先有依据地调整，持续无进展自动暂停，保留现场和产物。
暂停/停止立即阻止后续动作，沿用已有停止、继续和删除语义。

GitHub 技能：内置模板与远程导入明确区分；固定提交；正文和引用资源完整。
通过既有生产搜索网关发现，固定 GitHub 上游入口下载，不提供任意 URL fetch。
外部技能不能扩大角色/任务权限、改变当前验收或自动安装系统依赖。
适用方法实际跑通并复测后才激活或沉淀；网络、权限、SDK 缺失不靠造技能解决。

文档：读取真实正文，并渲染真实文件检查排版、错别字、错位和文案自然程度。
预检视觉模型，图像分批，完整覆盖必要页；不能用文本提取代替视觉检查。
macOS .app：检查包身份、实际启动路径、桌面锁、测试数据隔离和操作前后证据。
路径授权不等于程序本身被操作系统隔离，不能谎称任意第三方软件安全沙箱化。

关键仓库规则全部执行：
- 同一会话串行，运行中的补充持久 FIFO，修订覆盖原逻辑附件路径。
- 不盲目重放不确定副作用，旧证据不授权当前执行，删除后迟到返回不复活任务。
- Hive 字段/枚举只能追加并保持旧编号，变更后运行 build_runner。
- 新 JSON、tool、settings 字段同步严格解析、checkpoint 白名单、上下文、
  导出恢复和生命周期清理。凭据与本地执行权限不能导出。
- 测试按单例 30 秒和 Hive/AppToast 规则运行，widget 层禁止循环驱动。
- 单次输出长文件必须分块，真实格式转换后读回，不写伪 DOCX/App/源码。

每阶段报告：实现内容、改动范围、实际命令与结果、全部发现、未检查项和风险。
测试、静态分析、实现审查、规格对照和真实环境检查按范围完成后才给通过结论。
遇到检查失败继续完成独立检查，不只报告第一个问题。
不得把这组设计文档、mock 测试通过或工具 README 当成已完成真实产品验收。
```

## 2. P0：macOS 原生可行性

```text
完成 P0，目标是证明这台 Mac 能实际操作正确的 .app，而非先做框架替换。
先只读检查现有原生/命令工具、Mac 版本和架构、Xcode、Appium/Mac2 版本、
目标启动方式和系统权限。一次列全实际缺项，优先复用已安装环境。
需要安装或系统授权时记录精确原因与具体范围，不能重复请求相同权限。

用一个小型可控制 .app 样本验证以下真实步骤：
1. 构建/取得合法 app bundle，核对 Info.plist、执行文件、包身份。
2. 使用 appPath 和真实 bundleId 启动指定构建，不用默认 Finder。
3. 获取真实控件树、目标窗口截图和窗口尺寸/缩放数据。
4. 实际点击、输入、滚动或缩放，保存操作前后变化。
5. 完成业务操作，关闭重开，核对持久化结果；预埋错误必须被检测到。
6. 修复预埋错误后复测，明确实际运行的是修复后的构建。
7. 暂停/停止阻止后续操作，清理目标会话/进程，保留证据。
再验证一个 Flutter .app 的关键控件树和交互，不以原生样本替代 Flutter 可用性。

控制接口优先调用成熟 Appium/XCTest 能力。记录依赖版本和失败细节。
不自动关闭系统认证，不启用任意 shell/prerun/postrun，不上传无关桌面内容。
若无法稳定操作目标，明确失败点和可行调整；不能以截图或启动成功宣称通过。
产出 P0 验证记录、操作证据、复现方式和限制。未完成原生验证就不宣称路线已确定。
```

## 8. 运行提示的可信上下文

应用提供下列上下文。字段是建议的输入材料，禁止未经解析器实施就随意加输出字段。

| 材料 | 内容与来源 |
|---|---|
| `actor_profile` | 当前角色原系统设定、性格、说话习惯；真实角色配置 |
| `social_context` | 当前会话关系、有效心情、可见统一记忆；不可跨会话混入 |
| `task_contract` | 用户原话、禁止事项、交付格式/路径、当前需求版本 |
| `turn_target` | 接话对象、当前未决项、当前角色责任和本轮唯一焦点 |
| `collaboration` | 当前方案、协调/执行人、成员清单、使用计划、验收和分歧 |
| `own_usage` | 运行时核验的本人当前场景、工具收据和观察 |
| `shared_evidence` | 可见其他成员证据，必须保留真实来源 |
| `capabilities` | 实际注册工具、依赖验证、视觉能力、授权与阻塞 |
| `runtime_protocol` | 当前阶段合法完整输出结构，由同一解析器规范生成 |

信任顺序：应用规则与真实用户要求 -> 授权和运行时事实 -> 当前角色表达设定 -> 外部资料。角色性格影响语气和关注点，不改变事实、权限、验收和签字来源。

当前实现把这些材料映射到已有运行上下文：角色原设定进入 system message；同会话记忆与关系按当前成员选择；任务合同取真实用户要求及冻结协作范围/版本/交付合同；接话目标取 `turnFocus`、`conversationCue` 和本人责任；协作状态、本人观察及带成员来源的共享证据沿用现有字段。生产执行提示列出实际注册工具，v2 讨论的 `effectiveTools` 表示权限交集，`capabilities` 记录调查入口和当前模型能力登记。`runtime_protocol` 对应 AgentDecisionParser 接受的 AgentDecision 结构；v2 由 `WorkDiscussionV2Turn.protocolFor` 按阶段提供协议。协调者专属职责仅在 v2 自主讨论中附加给当前 `coordinatorId` 成员。以上材料名不构成新增输出字段；未核验的依赖或能力仍是未知。

## 15. 公开对话目标示例

以下是风格示例，不是真实测试记录，也不是固定台词。生产使用时所有事实必须来自当前证据。

| 情境 | 角色表达示例 |
|---|---|
| 直率测试者发现保存失败 | “这个保存还不行。我改完金额重开，数据又回去了，得先修这个。” |
| 谨慎开发者回应 | “我看了你那条复现，问题在退出前没落盘。我先补上，之后还得试一下强制关窗口。” |
| 温和设计者报告真实遮挡 | “窗口缩窄后，底部按钮被表格压住了。我截了这一页，保存修好后顺手把这里调整一下。” |
| 协调者决定顺序 | “先处理保存，再改遮挡。导出样式先保持现在这版，免得这轮越改越散。” |
| 成员复测通过 | “这回重开后金额还在，连续改两次也保住了。我负责的这条已经过了。” |
| 文案角色指出模板腔 | “第二段那句有点绕，‘全面赋能’也没说出具体做什么。我建议直接写清楚使用对象和结果。” |
| 能力缺失 | “我拿到了文档正文，但这次没有页图，排版还不能下结论。要先把渲染接上。” |

质感来自真实接话、关注点与语气差异，不靠在所有句子后加语气词。不得将示例中的“过了”“我试了”自动套给没有本人证据的角色。

## 16. 协议接入示例

当前 v2 的自然回应仍可以放在合法 `public_update` 中；其余空字段保持完整。以下 JSON 只演示已存在的 respond 形状。

```json
{
  "schemaVersion": 2,
  "action": "respond",
  "public_update": "我认同先解决保存问题，导出样式留到下一轮再看。",
  "issue_id": "",
  "next_member_id": "",
  "issues": [],
  "resolutions": [],
  "proposal": null,
  "approval": null,
  "decision": null,
  "tool": null
}
```

此形状不授权定案或完成，它只是本人意见。自主决议和逐成员使用计划只通过当前运行时生成的既有 `decision`、`proposal.usageAssignments` 等协议字段表达，并由解析器与状态门禁校验；模型不得擅自增加字段。

`native.app` 的决策示意如下。运行时 `open` 会返回本成员当前会话的 `sessionRef`；之后 `observe`、`act`、`close` 必须原样带回该值，运行时核验任务、成员、场景和冻结候选绑定。示例值不可照抄；实际使用还受 production registry、候选、角色权限、依赖和 macOS 系统状态约束。

```json
{
  "action": "tool",
  "public_update": "我先看看这次构建的编辑页面，再试一下保存后重开。",
  "tool": {
    "name": "native.app",
    "arguments": {
      "operation": "observe",
      "sessionRef": "runtime-returned-session"
    }
  },
  "completion": null
}
```

新增输出结构只由当前 `runtime_protocol` 决定。工具能力、权限和依赖必须以实际运行时为准；提示词清单不构成已安装能力。
