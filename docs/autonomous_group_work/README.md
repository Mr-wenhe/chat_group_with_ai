## 核心判断

可以实现具有明确运行环境和验收范围的自主协作。现有 v2 有讨论、候选冻结、独立审查和返工基础；缺少逐角色实际试用、macOS UI 操作、文档渲染检查和真实 GitHub 技能导入。需要中到大规模的工作模式扩展，暂没有必须重写整个 Flutter 应用的依据。

第一阶段采用单执行者，优先 macOS `.app`，同时规划网页、代码和文档的真实验收。Windows 原生测试与手机端测试排在 macOS 之后；多人并行制作和类似 `subagent` 的执行只记录路线，不提前实现。

## 开发入口

从 `03-prompts.md` 的“开发总提示词”开始，再依次执行 P0 至 P5。P0 的 macOS 真机操作证据是继续选定原生自动化路线的前提。只通过 mock 或单测不能确认原生 `.app` 可用。

01–03 是需求、设计和运行提示；04–09 是分阶段实际验证记录。只有报告明确记载的代码检查可视为已检查；单测、包构建和历史 P0 证据都不能替代报告要求的当前真实产品验收。
