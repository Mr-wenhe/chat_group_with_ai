# P1 状态、裁决与逐成员使用验证

日期：2026-10-13。范围：P1 的状态、模型协议、来源边界、单循环逐成员调度、签字与正式交付门禁、旧任务恢复、检查点与备份、面板。P0 记录见 `04-p0-validation.md`。未进入 P2。

已实现并完成本记录列出的代码范围检查。**这不是原生软件、文档视觉或真实多模型产品闭环验收通过记录。** 当前生产运行器尚无 P2 `native.app` 适配器，不会因为命令打印 tests JSON、退出码 0 或截图路径而生成有效原生使用凭证。

## 实现与调用链

| 范围 | 实现与边界 |
|---|---|
| 应用策略 | `autonomyPolicy.schemaVersion=1`，固定 `mode=coordinator`、`source=application` 与真实参与 ID。新任务由实际讨论入口建立；旧未完成任务显式继续后建立并重拟方案。旧完成历史不补造参与。 |
| 全员场景 | `usageAssignments` 包含成员、场景、目标、前置条件、步骤目标、预期、必达验收、能力、重置方式与需求版本。每人恰好一个不同场景，覆盖所有必达项。状态、提案和增量同步严格解析；新策略丢字段或未知版本阻塞。 |
| 制作职责 | 本轮材料与实现工作项由同一位合格制作人负责。普通试用资格不是开发资格，未验证技能标签不授予新策略的专业职责。制作人与 `task.characterId` 代表的实际 actor 分开；试用切换不改 `executorId`。只有明确用户更换成员决策可改原指定责任人。 |
| 真实意见与定案 | 继续使用 `approvals/issues/acceptances`。`approved:false` 与原消息保留。协调者本人真实回应产生独立 `coordinatorDecisions`，绑定本轮意见事件、版本和候选；不冒充用户答复。新策略普通方案/交付偏好分歧不默认交用户，实际失败、缺陷和未完成使用不能被定案覆盖。 |
| 收据来源 | `WorkToolResult.usageObservation` 为独立运行时类型，不从模型 JSON 或普通 `data/stdout` 解码。绑定任务、会话、本人、场景、候选、完整计划摘要与验证版本；区分业务核验与操作成功。复用事件详情及设备本地提交提交标记，无新数据库。 |
| 单循环试用 | `DefaultWorkTaskRunner` 在现有 reviewing 内逐人绑定 usage 工作段，仍由同一 `WorkAgentLoop` 使用当前成员的模型、人格与记忆。清理前任上下文/审批与观察引用。冻结候选操作前后核验；暂停停止后不派发后续动作。 |
| 反馈与复测 | 严格解析本人 `passed/failed/blocked` 反馈。失败记录复现、预期、实际、复测条件及真实来源，更新验收和缺陷；验证版本变化保守地使所有旧使用记录失效。阻塞不算使用通过。 |
| 完成守卫 | `deliveryReady`、本人签字入口、生产准备与正式封存投递均检查当前计划/候选/验收/全员使用；正式交付再核验本地详情摘要、提交标记、真实本人反馈与交付文件。保留 FIFO 和 arriving-input 的最终串行核验。 |
| 历史与恢复 | 新字段经 typed checkpoint、上下文投影与备份保留；恢复重映射角色、任务、会话和消息引用。导入项目未绑定、成员不可执行、版本失效；本地提交标记与执行权限不导出。协调决议历史窗口不形成累计轮次上限。 |
| 面板 | 分开展示制作人和当前成员，显示场景的待使用/本轮反馈记录及协调理由；不将待使用显示成通过。 |

## 实际命令与结果

完整日志在 `p1-evidence/`；多数运行过不止一次，下表记录合并回归和最后相关复测。所有单例均设 30 秒超时，widget 未增加循环驱动。

```sh
flutter test test/work_mode/work_collaboration_state_test.dart test/work_mode/work_discussion_v2_test.dart test/backup_restore_service_test.dart test/work_mode/default_work_task_runner_stage02_test.dart test/work_mode/work_task_coordinator_test.dart test/work_mode/work_agent_loop_test.dart test/work_mode/work_discussion_state_test.dart test/work_mode/work_context_builder_test.dart test/work_mode/work_task_checkpoint_test.dart test/work_mode/work_candidate_publication_test.dart test/work_mode/work_discussion_v2_panel_test.dart --timeout 30s --reporter expanded
```

结果：641 个通过，见 `p1-evidence/acceptance-641.log`。随后收紧材料同制作人、职业资格与指定人一致性，相关合同复测 154 个通过（`contracts-154.log`）。面板独立 2 个通过；恢复/循环/上下文/检查点/候选边界独立 333 个通过。

```sh
flutter analyze --no-pub
flutter build macos --debug --no-pub
git diff --check
```

结果：analyze 无问题；debug 构建产出 `build/macos/Build/Products/Debug/伴伴.app`；diff 无空白问题。构建有 Xcode arm64/x86_64 匹配目标提示，选择当前 Mac，并成功结束。构建后未启动真实 chat_group，未读写其生产 Hive 数据。

本轮未改 Hive 字段/枚举或 `@JsonSerializable` 模型，因此不需要重新生成 adapter。未改 gateway、依赖、凭据或 settings 白名单。原有 6 个用户修改文件和 mention 测试、设计文档保留；没有提交或发布。

## 检查发现与修复

| 严重级 | 发现、影响与处理 |
|---|---|
| 高，已修复 | 外部可声称协调/成员身份：新自主任务的角色状态更新只接受实际运行器；用户决策保持原用户入口，策略/收据/定案不能由外部登记。 |
| 高，已修复 | 旧使用记录可能覆盖新失败或复测：收据新增验证版本绑定；新的验证事实保守失效全员旧使用。 |
| 高，已修复 | 制作 actor 与用户钉定人不一致仍可能准备执行：方案、执行、交付及面板同步核验。材料也由同一制作人负责；普通试用/未验证技能标签不充当开发资格。 |
| 高，已修复 | 只有正向使用结果，失败无法进入修复：本人反馈严格分 passed/failed/blocked；失败进入既有验收/缺陷和真实复测，不能裁决通过。 |
| 中，已修复 | 新策略建立时旧 JSON 不含新空字段，被来源校验误拒：同步构造、解析和增量字段；当前策略丢字段阻塞。 |
| 中，已修复 | 启动策略迁移覆盖 waitingForApproval/interrupted，且遮住不确定副作用诊断：保留原等待状态与现场，显式继续建立策略；保留恢复核验失败原因。 |
| 中，已修复 | 协调决议累计后可能撞状态容量：当前有效决议与必要历史分别保留，窗口不成为累计迭代上限。 |
| 中，已修复 | 自动网络重试测试提前观察计数，第三次派发未开始就断言：等待实际三次启动及最终失败状态，修复测试等待条件；未改变生产重试阶梯。 |
| 低，已修复 | 初次 Dart 条件表达式可空下标的括号错误、导入遗漏、测试 final 字段误赋值、lint：全部修复并复测。 |
| 检查命令更正 | 曾误写不存在的 `test/backup_service_test.dart`；其余独立检查继续执行，改用实际 `backup_restore_service_test.dart` 完成 65 个用例。不能把那次失败命令算通过。 |

## 规格与边界对照

| 要求 | 已完成代码检查 |
|---|---|
| 缺成员/重复场景/漏必达项 | 方案门禁阻塞；不能靠其他成员的认可补足。 |
| 借用、跨任务/会话/场景、旧计划/候选/验证版本 | 状态绑定与运行时类型校验拒绝；本地详情与提交标记再核验。 |
| 偏好反对、真实失败 | 反对原样保存并由真实协调者定案；失败/开放缺陷/未完成使用持续阻塞。 |
| 代签与冒用角色 | 模型协议不接成员替代身份、收据或权限；公开增量不能新增角色状态/签字。 |
| 指定制作人、逐人操作 | 制作人一致性与 actor 分离测试；前任工具结果、审批及观察引用清理。 |
| FIFO、新输入、停止和删除 | 既有最终串行守卫与取消/删除门闸回归；新增使用提交前后检查取消和待处理输入。 |
| 旧完成、未知版本、显式继续 | 历史不补造；未知保留阻塞；旧未完成需重拟方案。 |
| checkpoint/压缩/备份/恢复 | 实际单循环暂停检查点、新字段往返和 copyWithNewIds 重映射测试；导入不获得本地执行资格。 |
| 不设累计预算 | 未添加任务费用/时长/轮次限制；复用单次时限、网络阶梯、进展保护及现有索引/存储边界。 |

工作区自检包括全部新增文件与相关生产差异，确认来源、失败路径、状态门禁和提案同步，不以提示词作为唯一改动。较长状态文件拆为同一 Dart library 的 part，原校验/错误处理保持；没有第二执行循环。

## 未检查项与限制

1. 未跑真实 LLM 的新自主群任务与每人实际原生使用；模型、SDK 结果测试桩只验证合同和防伪边界。
2. 未实现/验收 P2 Appium/Mac2 生产适配、`.app` 候选封装、真实目标窗口/焦点/缩放、测试数据隔离、全局桌面锁、SDK 会话清理与恢复；未实现 P3 渲染、图像覆盖与实际视觉模型请求，未实现 P4 GitHub 技能或 P5 完整产品验收。
3. `WorkUsageObservation` 是可信适配器的来源合同。后续适配器仍须核验真实操作、目标身份、观察/结果文件及摘要，才能填业务核验；当前类型与提交标记不能替代这些实际环境检查。场景语义与真实差异也须现场核验，不能把不同场景 ID 当充分证明。
4. 应用层防伪不声称能抵抗同一系统用户权限下任意恶意进程篡改，也不声称普通路径授权能将第三方程序系统沙箱化。
5. debug `.app` 构建与包身份已核对（`p1-evidence/bundle-identity.log`），未启动该生产 App、未检查其控件树或操作效果。构建成功不等于通过 P0/P2 的实际操作要求。
6. 没有做全仓库安全审计、所有平台构建、所有测试或发布。当前结论仅限上述 P1 代码范围。
