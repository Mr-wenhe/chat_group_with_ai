一个本地优先的 Flutter 应用：创建多个 AI 角色，让它们在同一群组里自动互动对话，并额外具备工作模式（让 AI 真正执行文件/命令任务）与生产级联网搜索两个差异化能力。支持 8 家国内主流厂商 + 4 种自定义上游协议，跨 Windows/macOS/iOS/Android 四端，数据全部存本地 Hive，无后端。

三、伴伴的差异化优势（必须守住并放大）

  1. 工作模式（agentic 执行文件/命令）—— 所有竞品都没有。角色不只是"聊"，而是能替你干实事（写文件、跑命令、查文档）。这是从"玩具"到"工具"的质变，应作为头号品牌卖点。
  2. 生产级联网搜索—— 内置 Tavily/Brave/Gateway，带查询规划、来源引用、Prompt Injection 防护；竞品多靠扩展且安全责任甩给用户。
  3. 国内模型原生友好—— 8 家国内厂商 + 4 种协议，对中文用户零门槛；多数海外竞品默认面向 Ollama/OpenAI。
  4. 跨 4 端 + 本地优先—— Windows/macOS/iOS/Android 一体，数据全本地；RisuAI 也跨端但 agentic 缺失。
  5. 主动私聊（前台主动联系）—— 角色会按冷却规则主动找你聊，竞品多为被动响应。

四、10 条优化建议（按优先级）

P01. 接入 Tavern v2 角色卡生态（导入 / 导出 / 社区）
对标：SillyTavern / RisuAI / mostaron（均支持 V2 卡，可对接 Chub、AI Character Hub 上海量社区角色）。
现状：自研人设表单，用户必须自己写人设，无现成角色可用，冷启动成本高。
建议：支持 PNG/WebP/JSON（V1/V2）角色卡导入与导出；内置"角色广场"入口（可先对接现成社区 API，后期做自有轻量后端）。这是最大获客杠杆——瞬间拥有上万现成角色。
价值：用户留存与传播的核心飞轮，直接补齐与 mostaron 的短板。
P02. 升级群聊发言引擎：加"AI 智能选择器" + "合并角色卡(APPEND)"
对标：SillyTavern（Natural/List/Manual/Pooled 4 策略 + APPEND 合并卡） / Aithos（AI selector 按上下文选发言者）。
现状：纯随机挑 1–2 人、最多 3 轮；群聊像"抽签"而非"自然接话"，沉浸感弱。
建议：① 新增"自然模式"——用一个轻量 selector 模型根据上下文决定谁该接话（你已有 HumanizedChatOrchestrator 的意图评分，可升级为发言权仲裁）；② 支持 APPEND 模式把所有在场角色的人设/世界观合并注入，让 AI 区分声音。保留现有随机/手动模式。
价值：群聊从"演示 toy"变"真·群像戏"，是产品内核的体验跃迁。
P03. 引入世界书 / Lore Book（关键词触发背景注入）
对标：mostaron / RisuAI / SillyTavern（World Info 递归扫描）。
现状：只有群组摘要记忆（年-周），无结构化世界观；长对话易主题漂移。
建议：增加"世界书"概念——按关键词命中把设定/背景/术语注入上下文；支持分层（置顶常驻 + 关键词触发 + 每角色独立启用）。与现有 GroupMemory 并存而非替换。
价值：解决"群越聊越散"，是角色扮演沉浸感的刚需，成本远低于自研角色卡。
P14. 把"工作模式(agentic)"做成头号差异化卖点并完善移动端
对标：无直接竞品（SillyTavern/Agnai/RisuAI/mostaron 均无 agentic 执行）。
现状：能力最强但藏在"房间开关"里，用户无感知；移动端审批/文件沙盒体验未打磨。
建议：① 把 agentic 提升为人设可勾选的"技能"，而非隐藏模式；② 独立产品页/宣传点"会干活的 AI 群"；③ 移动端完善审批流、文件沙盒、任务进度浮层；④ 扩展工具（浏览器、图像生成、定时任务）。
价值：这是你与所有角色聊天 App 的代差护城河，应全力放大。
P15. 联网搜索开放为可插拔 Provider + 社区扩展 SDK
对标：SillyTavern 的扩展生态（正则/预设/出图/翻译/搜索/情感 sprite）。
现状：搜索/工具全内置封闭，官方维护成本高，用户无法贡献。
建议：把搜索 Provider、TTS、图像、翻译抽象为可注册插件接口；提供最小扩展 SDK 与示例；官方只维护"生产级网关"，其余交给社区。复用现有 clean-architecture 分层。
价值：用社区杠杆补生态短板，同时降低官方长期维护负担。
P16. 降低安装与分发门槛，主打移动端"即用"
对标：mostaron（单 APK 即用） / RisuAI（真移动应用，5 分钟上手）。
现状：混合发布流程重（CI + 本地脚本 + 签名），普通用户望而却步；首屏引导偏开发者向。
建议：① 提供免签名/自包含安装包或一键安装器；② 移动端首屏引导：角色卡一键导入 + API 一键预设（你已有国内厂商，可内置快速配置）；③ 考虑 TestFlight / 直链 APK 分发，缩短"下载→聊天"路径。
价值：把"本地优先"的优势转化为"装机即用"，直接对线 mostaron 的移动端体验。
P27. 构建角色 / 群组 UGC 分享与一键迁移
对标：mostaron 用户的"换手机如何迁移全部角色/记录"痛点；SillyTavern 角色卡可移植。
现状：有对话导出（已脱敏）与 .cgbak 备份，但角色/群组分享与跨设备迁移路径不顺畅。
建议：① 角色/群组配置一键导出为可分享文件（含人设、世界书、记忆摘要，不含密钥）；② 导入时自动重绑 API；③ 中期做轻量云端角色广场（见建议 1）。
价值：降低迁移摩擦，促进用户间自发传播。
P28. 群聊规模与稳定性工程（>5 角色防崩）
对标：AutoGen / CAMEL 已验证——超过 5 个 agent 时发言 selector 易抽风、token 暴涨。
现状：设计面向小规模 demo；缺乏群级预算护栏与长上下文管理。
建议：① 提供"自定义发言 selector"钩子，避免纯随机在大群里失衡；② 群级轮次/token 预算 + 防刷屏（你已有 hourlyReplyLimit，可扩展为群级）；③ 长对话上下文分层/压缩，保护窗口。
价值：让"大群戏"可用，避免用户加几个角色就翻车。
P29. 记忆系统升级：结构化长期记忆 + 记忆召回 + 跨群统一
对标：SillyTavern（置顶记忆 + 递归世界信息 + 自动清理） / mostaron（置顶+最近记忆双轨）。
现状：已有 CharacterMemory / RelationshipState / GroupMemory 分层，基础不错，但仍是"整段摘要注入"，无检索式召回。
建议：① 记忆从"整段注入"升级为"关键词/向量召回"（只取相关片段，省 token）；② 跨群组同角色的统一记忆；③ 关系图谱可视化；④ 记忆达上限自动清理（mostaron 已有，你可做）。
价值：在已有优势上继续拉开与竞品的记忆体验差距。
P310. 多用户 / 协作（中长期可选）
对标：Agnai（唯一可信多租户共享服务器，适合写作小组/朋友圈协作角色扮演）。
现状：纯本地单用户；与"本地优先"定位一致，但错过协作场景。
建议：若定位"AI 角色群组社交"，可加轻量可选后端做共享群组/协作写作（可选开启，默认关闭保隐私）；若坚持纯本地，则至少把建议 7 的"导入导出迁移"做扎实。先不做也行，但要预留数据模型。
价值：潜在第二增长曲线，但优先级最低，避免过早加重发布/合规负担。

落地节奏建议

  • 第一波（P0，1–2 个迭代）：角色卡导入（建议1）+ 群聊智能选择器（建议2）+ 世界书（建议3）。这三项直接把"群聊沉浸感"拉到竞品水平，投入可控。
  • 第二波（P1）：放大 agentic 卖点（建议4）+ 扩展 SDK（建议5）+ 移动端即用（建议6）。把独有护城河变成品牌，并降低装机门槛。
  • 第三波（P2/P3）：UGC 分享迁移（7）、大群稳定性（8）、记忆召回（9）、多用户（10）。

一句话：补"群聊生态三件套"（角色卡/选择器/世界书）追上同行，再把"会干活的 AI 群"这个无人区做成你的招牌。
