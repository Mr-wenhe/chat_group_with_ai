# 工作模式使用手册（v2 协作）

**适用版本：** 2.3.5+14
**最后核对：** 2026-10-16
**适用范围：** 群聊工作模式的 v2 协作流程。私聊工作模式仍走旧流程，差异集中在[私聊与旧任务的差异](#私聊与旧任务的差异)一章。

## 先读结论

工作模式在群聊里组一个**围绕任务的工作团队**：从当前群挑出做这件事需要的成员，先查证问题、形成方案并逐人确认，再按职责制作成果，由另一名成员独立审查，有问题就返工复测；全部验收项通过、且当前团队每位成员都认可同一个版本之后，才正式交付。

三条通道各管一段，不要混淆：

| 通道 | 承载什么 |
|---|---|
| 群聊消息 | 协作事实。成员的提问、查证、异议与认可，都以普通消息出现在聊天流里 |
| 任务面板 | 状态与证据索引。阶段、待决事项、本轮候选版本、验证结果、成员认可 |
| 文件 | 实际成果。工作区里的当前文件、可回退的快照、每轮冻结的候选副本 |

你不需要读模型之间的协议。内部状态、工具参数与校验细节留在面板详情里，公开气泡只写成员的自然表达。

真正需要你决定的只有两类事：**目录授权**，以及**有影响的操作**（写入、删除、命令、安装等）在执行前的审批。其余流程团队自己推进；需要你决策时，群里和面板会同时提示。

## 五分钟上手

### 步骤 1：准备一个能干活儿、且有凭据的角色

在「设置 → API 配置」中配好模型，并绑定到至少一个角色。角色还需要打开 Agentic 能力，工作模式才会把它当作可用的团队成员。

请把角色的**职业、技能和职责**填准：团队选人、责任划分和资格校验都用这些信息判断，填得含糊会让不合适的人被选进来，或让合适的人进不来。

### 步骤 2：授权工作目录

打开「设置 → 工作模式 AI Agent → 授权目录」，添加一个或多个目录。首次选择会出现一次确认框，列出规范化后的完整路径、能力声明（「能力：可读取、可写入。」），以及“目录内容可能按需发送给当前角色的 API”这一披露。一次确认可以覆盖多个目录。

授权记录只属于本 App；移除记录**不会**删除磁盘上的目录。目录被移动、删除或系统权限变化后，设置页会显示不可用，需要重新授权。

### 步骤 3：在群聊打开工作模式

进入目标群聊，在会话控件行打开「工作模式」。它只对当前会话生效。打开后该群的空闲自动发言暂停，界面提示「工作模式中，自动发言已暂停」；关掉开关即恢复。

### 步骤 4：发一个可验收的需求

写清目标、交付形式和完成条件。**不要写“让谁来做”**——v2 由团队自己选人，`@` 只在任务首次路由时起作用，写错了反而限制它。

> 在授权目录 `/work/notes` 下，把这三次周会记录整理成一份 Markdown 周报，包含本周进展、风险和下周三件事。放在同一目录，文件名 `weekly-report.md`。

### 步骤 5：等讨论跑完，中间不用管

面板会显示「等待相关团队查证问题并逐人确认当前方案。讨论自动进行，你无需操作；要补充要求直接在群里说。」成员发言以普通消息出现在群聊流里，你可以直接看。

想自己指定执行人，就在面板上点候选——面板上写着「你无需操作；群内也会自动推举。点选即直接指定。」**不点也没关系**，团队会自己推举。

### 步骤 6：看候选与审查，认可后交付

进入制作后，每一轮产出一个候选交付版本；测试或专业审查的报告回到群里。认定通过后，面板的认可区逐条显示「认可 某人：同意 · 第 N 轮候选 · 验证版本 N」；全部验收与认可齐全才正式交付。

不满意不必等它交付：在面板回复框里说，或者直接在群里说。

## 首次配置

### API 配置建议

- **一个角色一个模型**。参与讨论的每个成员用自己的模型作答，不会由一个角色一次编造全队发言，也不会拿协调者的模型冒充别人。
- **如实声明模型能力**。在角色的模型能力里勾选是否支持逐字输出、是否支持工具调用；这两项关掉后工作模式无法启动。上下文窗口与最大输出的声明值决定一次请求能读多长、写多长——声明写大了由上游返回错误暴露，写小了任务会更早撞上窗口限制。
- **结构化决策不稳定时**（空响应、写坏的 JSON），同一请求只做一次有限修复；仍失败会归类为协议错误，面板给出重试或修改请求的出口，不会把原始响应直接当成可执行命令。

### 授权多个目录

可以同时授权源码、文档和测试夹具等目录：

1. 在设置里选择目录；
2. 检查确认框中的完整路径与读写能力；
3. 确认后记录才落盘；
4. 目录移动、删除或权限变化后重新授权。

应用只在需要时检查目录可达性，不会递归预扫描你的磁盘。

### 重新授权和移除

- **重新授权**：目录还是同一个业务目录，只是访问状态失效时使用；
- **添加目录**：把新的根目录纳入工作范围；
- **移除**：只撤销 App 的访问记录，不删除目录及其内容。

任务请求授权范围外的路径时，面板会暂停，并提供授权目录的入口。

## 界面与任务面板

### 面板由谁承载

执行面板挂在 App 根部，不绑定任何页面，因此你在设置、群聊、私聊和角色列表之间来回切换，任务都不会中断，也不会被页面销毁打断。

面板是**非模态**的：它不锁住整个 App，你可以在它运行的同时做别的事。

### 面板结构

自上而下：

| 区域 | 内容 |
|---|---|
| 头部 | 标题「工作任务」，以及「查看历史任务」「收起执行面板（任务继续运行）」两个入口 |
| 任务标签栏 | 每个标签对应一条任务，标签名取你指令的第一行（没有就显示「未命名任务」）。最多同时显示 4 条：当前会话里正在执行的任务优先，其它会话里正在执行的也会显示，终态、排队和暂停的任务不占标签 |
| 折叠提示 | 还有未结束的任务没进标签栏时显示「本会话还有 N 个未结束的任务未在标签栏显示，可在「历史任务」里查看。」 |
| 任务详情（默认收起） | 由「任务详情」开关展开，内含「任务需求」「运行状态」「执行细节」「异常与日志」四张卡 |
| 问题与方案详情 | 折叠区，展开后是群讨论的问题、决议、候选、验收与认可台账 |
| 执行动态 | 「执行动态 · 实时公开输出」，任务的公开进度流。等待时显示「等待公开执行动态…」，更早的动态收进「之前的 N 条动态」 |

没有可显示的任务时，面板显示「没有正在显示的任务，可从「历史任务」里重新查看。」

### 任务状态

面板用十个短标签表示任务当前在哪一步，展开详情后可以看到对应的整句说明：

| 短标签 | 说明 | 要不要你动手 |
|---|---|---|
| 排队中 | 任务正在排队 | 不用，等前面释放执行槽 |
| 规划中 | 正在规划下一步 | 不用 |
| 执行中 | 正在执行工具 | 不用 |
| 等待审批 | 等待你批准当前操作 | **要**，批准或拒绝 |
| 已暂停 | 任务已暂停，等待继续 | **要**，处理完前置条件后点「继续」 |
| 已中断 | 任务已中断，等待继续 | **要**，点「继续」恢复 |
| 已完成 | 任务已完成 | 不用；可以追问、查看或撤销 |
| 部分完成 | 任务部分完成 | 看详情决定要不要追问 |
| 执行失败 | 任务执行失败 | 若是可恢复的故障，**要**你点「重试」 |
| 已停止 | 任务已停止 | **要**，点「继续」接着跑 |

### 底部按钮

按钮按当前情况出现，不是每个问题都把全部按钮摆给你：

| 按钮 | 什么时候出现 |
|---|---|
| 「回答待决问题」/「处理 N 项待决事项」 | 有未决事项等你决定 |
| 「指定最终执行人」+ 候选角色 | 还没有确定执行人、且有候选时。旁边写着「你无需操作；群内也会自动推举。点选即直接指定。」 |
| 回复框 | 有需要你回答的问题时（群讨论提问、模型提问、或修订目标需要澄清） |
| 「批准」/「无撤销执行」/「拒绝」 | 停在等待审批，且有未批的操作。不可撤销的操作显示为「无撤销执行」 |
| 「稍后处理」 | 任务未结束，且处于已暂停、已中断或等待审批。「保持当前检查点等待，不会批准或降级任务。」 |
| 「授权目录」 | 需要新的目录授权 |
| 「帮助安装工具」 | 缺少任务需要的工具 |
| 「选择视觉模型」 | 任务要读图片，而当前角色不具备视觉能力 |
| 「确认执行人」 | 群内推举的人选与已钉定的执行人不一致，需要你确认 |
| 「确认交付 N 个文件」 | 任务暂停，且有等你确认的交付物 |
| 「重新授权」/「重新生成计划」 | 失败原因属于授权范围或计划失效 |
| 「查看冲突」 | 文件在你批准之后被外部程序改动 |
| 「从头开始」/「重试」 | 二选一，出现条件不同，见[停止、继续、从头开始、删除](#停止继续从头开始删除) |
| 「停止」 | 任务未结束 |
| 「继续」 | 任务可以接着跑。不可用时按钮变灰，悬停会说明原因 |
| 「撤销」 | 任务已结束，且有可回退的快照 |
| 「回到对话」 | 常驻，跳回该任务所在的会话 |
| 历史任务里：「在标签栏打开」「删除任务」 | 见[停止、继续、从头开始、删除](#停止继续从头开始删除) |

### 三种可见状态

| 状态 | 你看到什么 | 任务是否继续 |
|---|---|---|
| 展开 | 完整步骤、公开动态、审批与恢复按钮 | 是 |
| 折叠 | 底部的任务条 | 是 |
| 隐藏 | 页面右下角的工作任务入口 | 是 |

离开当前页面同样不影响任务：任务由全局协调器持有，不由页面持有。

## 一次群任务的一生

下面是一次群任务的完整路径。图里的环不是固定轮次——每次只调度能回答当前问题、执行当前工作或验证当前成果的成员；可以一轮查证就结束，也可以反复修订。**不会为了凑“至少两轮”追加废话，也不会因为“超过六轮”被截断。**

### 1. 选择相关团队与协调成员

从当前群成员里按任务所需能力挑出工作团队，并记录分工。协调职责由团队内合适的成员兼任，不新增一个虚拟经理。

**你会看到**：面板运行状态里显示「阶段：… · 当前成员：…」。

**要你做什么**：不用做什么。想抢先指定执行人时，点面板上的候选；否则团队会自己推举。

### 2. 需求梳理与资料查证

团队围绕任务提出问题、给出证据、查证资料。允许在这个阶段读代码、搜资料、看已有证据，但**不允许**在方案没确认前先写个原型来替掉讨论——那会变成“先做后想”。

**你会看到**：成员在群聊里发言，有人提问，有人贴出查证结果，有人指出矛盾。发言瞄准“短、具体、接住别人的问题”，所以气泡里的正文是节选；被节选的完整正文会以 `完整公开正文.json` 附件挂在同一条消息上，面板的「问题与方案详情」里也能看到全文。

**要你做什么**：不用做什么，除非某个问题必须由你回答——那时面板会给出回复框。

### 3. 形成方案并逐人确认

团队汇总出可执行方案，确认所有已知疑问都有答案、都有明确取舍或已由你处置。

**你会看到**：面板在有待解决问题时显示「待解决：…」。

**要你做什么**：通常不用。v2 **不要求**你批准开工，也不显示“理解度百分比”、更没有“达到 100% 才能执行”这条规矩——那是旧任务的判据。

### 4. 按职责制作

由具备能力的成员实际制作。工作区里出现真实产物，不是只有描述。

**你会看到**：面板显示「已执行 N 个动作 · 按有效进展继续」。v2 群任务**没有累计上限**：不数“N/100 步”，也不设总时长上限，只要每一轮都带来新的问题、证据、验收或文件内容变化就继续。反复失败、持续没有进展或无法解决的阻塞才会停下来求助。

**要你做什么**：写入类操作会弹审批，按提示批准或拒绝。

### 5. 冻结本轮候选

每一轮送测都留存一份**只读的候选副本**和它的清单，记录相对路径、哈希、需求版本与团队版本。

候选冻结之后内容不会再被覆盖——所以它在后续工作文件被继续改动的情况下，仍然能独立打开、独立核对。出现修复就产出下一轮候选。

**你会看到**：群聊里出现一条带文件附件的消息「候选送测 `第 N 轮`，文件已冻结，等待本轮审查。」；面板的「问题与方案详情」里同时显示「候选 第 N 轮候选 · 状态」。

**要你做什么**：不用做什么。

### 6. 测试或专业审查

审查由**不同于该版本主要实现者**的合格成员承担。软件按当前验收项实际运行；文档类交付则核对内容范围、事实逻辑、结构、格式和能否打开。审查结果绑定在该候选版本上，不靠“读一遍源码”替代运行验证。

**你会看到**：审查报告以附件消息回到群聊（「本轮审查报告 `第 N 轮`，对应摘要 …」）；面板显示「审查 …」「工作项 …：某人 · 状态」「验收：方法 · 状态」「版本 … · 证据 …」。

**要你做什么**：不用做什么，除非缺人。缺测试角色时团队会弹待决问题请你决定：候选来自已有角色库，每项都标出姓名、职业与所用模型，影响写明「只加入本次任务的 测试 责任；保留目录、工具和模型治理边界。」——补进来的人**只加入本次任务**，不改该群的永久成员名单。面板上也有「去补充角色」入口。

### 7. 返工复测，或逐成员认可

审查不通过或有有效异议时，回到第 4 步：定位原因、确定修复、修改、复测，并检查受影响的回归。

通过之后，当前团队的**每一位**成员都要对同一个版本明确认可。认可绑定任务、需求版本、团队版本、候选、文件摘要与验证版本；任一要素变化，旧认可只作历史、不再满足当前交付。

**你会看到**：面板逐条显示「认可 某人：同意 · 第 N 轮候选 · 验证版本 N」；要素变过的旧认可会显示成「已失效」。

**要你做什么**：**v2 里没有你的签字按钮**——认可是 AI 成员的台账，不需要你逐条签。你的出口是下面两种，都在待决弹窗里：

- **明确豁免**：记录某项验收不做的原项、原因、适用版本和未验证风险，状态标为 `waived` 而**不是** `passed`；
- **记录人工验收**：你亲自验证过某项，结果标为 `manual`，不会被伪装成自动测试日志。

### 8. 正式交付

验收与逐成员认可齐全后正式交付，交付版本连同验收结论和签字一起封存，封存记录不会被覆写。

**你会看到**：群里出现正式交付消息，写明本轮编号、是否含用户明确豁免、是否含人工验收，并以「验收与逐员认可已封存」结尾——例如「正式交付 第 N 轮，含用户人工验收，验收与逐员认可已封存。」

**要你做什么**：不用做什么。文件成果合格但消息附件发送失败时，任务仍算完成，只重试发送，不会重新生成或重复返工。

## 你需要动手的时刻

### 待决弹窗

需要你判断时弹出，标题是「需要你的决定」，多项时显示「待处理事项 N/M」。它会说清：需要决定什么、当前事实、成员分歧、已尝试的方法、可选方案及影响。你可以自由输入「补充建议或解释」，也可以点按钮：

| 按钮 | 含义 |
|---|---|
| 「提交建议」 | 你的建议先落盘，再被成员重新检查条件。建议没解决问题时会说明具体还缺什么，而不是把同一个弹窗再弹一遍 |
| 「此项先放着」 | 暂缓。**永远不等于通过**，也不算豁免；团队会先推进不依赖它的工作，其余工作做完后**再次提醒**你 |
| 「明确豁免」 | 你决定某项验收不做，记录原因与未验证风险 |
| 「记录人工验收」 | 你自己验证过了，记为用户人工验证 |

同一个问题在重建页面、重试或重启之后不会反复弹。关掉弹窗只表示“暂未作答”，待决事项始终可以从面板重新打开。

### 审批卡

有影响的操作在执行前弹卡，标题「任务变更需要审批」（通用操作是「工作任务需要审批」），列出：

- 为什么需要这次变更；
- 将做什么；
- 准确路径；
- 命令影响。

按钮为「允许本次范围」「拒绝并暂停」；不可撤销的操作显示「仍然执行（无法撤销）」。**批准只授予当前任务、当前明确范围**，不会把你的磁盘变成永久白名单；下次涉及新路径还会再问一次。

### 面板回复框

需要你回答时，面板里出现回复框，提示语区分三种情况：

| 提示 | 场景 |
|---|---|
| 「请回答群讨论的问题」 | 群讨论里有问题需要你定夺 |
| 「请回答模型的问题」 | 模型执行中遇到必须要你回答的问题 |
| 「请明确修订目标」 | 你说“改一下”但历史里有多个候选文件，需要你指明是哪一个 |

输入框提示「输入回复…」，按钮「发送回复」。目标澄清这类问题会给出**可点的候选**——点一下就等于提交完整路径。上次回复没被认出来时会提示「没能从上次回复里认出要改的文件，请点选下面的选项，或回复完整路径。」

### 其它需要你点的场合

- **指定最终执行人**：讨论阶段可抢先点选，跳过推举。
- **选择视觉模型**：任务要读图片而当前角色不支持时。应用**不会**自动切换到别的模型，只会请你选一个已配置的。
- **确认执行人**：群内推举的人选与你此前钉定的执行人不一致时。
- **授权目录** / **帮助安装工具**：范围不够或工具缺失时。
- **确认交付 N 个文件**：交付物需要你确认时。
- **查看冲突**：文件在你批准后被外部程序改动，任务进入冲突状态，面板列出冲突路径。系统**不覆盖**外部内容，等你决定重新读取、重新规划还是手工处理。

## 停止、继续、从头开始、删除

### 停止

「停止」把任务置为已停止，**但它是一个可继续的终态**：检查点、已完成步骤、已提交的操作、产物路径和协作记录都原样保留。

停止**不会清空你已经发出的输入**。如果停止时队列里还有你的追问，系统会当场问你是接着执行它们还是丢弃——你的输入不会静默消失。

### 继续

「继续」从同一个安全检查点接着跑，是已停止任务的唯一出路。

按钮不可用时（变灰）会给出原因：

| 不可用原因 | 你要做什么 |
|---|---|
| 「请先批准当前操作。」 | 先去批准或拒绝 |
| 「请先回答上方模型问题。」 | 先在回复框里回答 |
| 「请先在上方明确要修订哪一个文件。」 | 先在回复框里指明目标文件 |
| 「请先完成群讨论并确定最终执行角色。」 | 等讨论跑完；缺人可以补人 |
| 「请先选择支持图片的视觉模型。」 | 选一个视觉模型 |
| 「请发送明确的测试、构建或分析请求后继续。」 | 明确写出要跑的命令 |
| 「任务正在执行，无需继续。」 | 什么都不用做 |
| 「任务已结束，无需继续。」 | 任务已经结束了 |

### 从头开始与重试

这两个按钮互斥，出现条件不同：

- 「**重试**」用于可恢复的失败（链路、模型临时故障等），从安全检查点重试；
- 「**从头开始**」用于你主动停止过的、且没有留下产物的任务。

**v2 协作任务不提供「从头开始」**：它会清空整块协作记录（问题、方案、候选、认可），代价太大。停止过的 v2 任务只有「继续」这一条路。

### 删除任务

在「历史任务」里打开任务详情，底部有「删除任务」，确认框问「删除这条任务？」，并说明「任务记录和执行日志都会被删除，无法恢复。…已经生成的文件不会被删除。」

这是**真删除**。删除之后：

- 该会话的下一条工作请求会**新建**一条任务，不会继续挂在这条记录上、也不会复用它的产物路径；
- 该会话的模型可见聊天记录从删除时刻起**划一条线**：新任务看不到这条线之前的群聊内容。这**不影响**你的聊天消息本身——消息还在，普通闲聊照常，磁盘上的产物也不受影响。

标签上的 ✕ 是另一回事：它只是关掉这个标签（「关掉这个标签（记录保留在历史任务中）」），任务记录仍在历史里。

### 两种清空不能混

会话菜单里有两条，差别是实质性的：

| 菜单项 | 删除内容 | 保留内容 |
|---|---|---|
| 「清空聊天记录（保留记忆与任务）」 | 只删消息，以及指向消息的设置（消息索引、会话摘要、已读位置、重试记录） | 记忆、关系、任务、工作区全部保留 |
| 「清空对话（含记忆与任务）」 | 消息 + 场合记忆 + 关系 + 任务 + 工作区 | 角色、群聊、API 配置、主题、目录授权保留 |

两者都只清理 App 内的工作模式事件日志和撤销快照，**不会**删除授权目录里的真实文件。

## 权限与审批

### 默认权限矩阵

| 操作 | 默认行为 | 可能的额外门禁 |
|---|---|---|
| 列目录、读取文本、搜索源码 | 授权根内自动执行 | 敏感文件需要精确读取确认 |
| 只读命令 | 自动执行并流式显示输出 | 命令、工作目录仍要通过策略校验 |
| 联网搜索 | 按搜索优先级自动尝试 | 登录、验证码、付费墙会暂停 |
| 创建、写入、Patch、重命名 | 先显示变更计划 | 普通写入确认可在设置关闭；新路径、无快照仍会再确认 |
| 删除、覆盖、安装、提交、依赖下载 | 始终显示具体审批 | 删除和不可逆操作不能被普通写入开关关掉 |
| 目录外路径 | 不执行 | 重新授权后继续 |
| 密码、登录、验证码、交互式菜单 | 不代填 | 面板暂停，由你手点继续或在外部终端完成 |
| 读取浏览器页面上下文 | 当前版本没有可用的运行时，视为不可用 | 需要浏览器能力时任务应阻塞或走人工验收，见[已知限制](#已知限制) |

### 普通写入前确认可以关

设置里的开关写着「关闭后仅普通、可撤销写入不再重复提示。」关掉它可以减少低风险写入的重复确认，但下面这些**始终**保留：

- 「删除文件和不可撤销覆盖始终需要确认，无法关闭。」；
- 安装工具、依赖下载、Git 提交；
- 跨目录或超出已批准范围；
- 敏感文件读取；
- 影响不确定的命令。

### 命令

命令由可执行文件、参数和工作目录构成，不走隐式 shell 拼接。系统会检查可执行文件与工作目录是否在允许范围、阻止路径穿越与符号链接越界、分开显示 stdout/stderr，并对超时、输出过大、密码提示和交互菜单安全终止或暂停。

构建和测试**默认不自动执行**：只有你明确说“运行测试”“构建”等，才会规划这些步骤，并在需要时再次请求命令审批。

## 连续追问与附件

### 任务未完成时

新输入进入当前任务的 FIFO 队列：旧任务继续跑，新追问排队显示，旧任务释放执行槽后按提交顺序处理，沿用同一会话的授权范围、已确认路径与阶段信息。**不会取消旧任务，也不会丢掉你的输入。**

### 修订同一个文件

明确说了“刚才生成的同一个文件”“上次那个文件”“当前文件”这类修订语义时，系统会**钉住原交付物路径**，不会因为重名自动生成 `-1`、`-2` 副本。只有明确的新建请求遇到重名，才允许自动改名。

这条钉定只作用于**同名文件**：任务里的脚本、素材、分段源文件等其它路径按普通规则解析，不会被吸到交付物上。

只说“把它改一下”而历史里有多个可能文件时，系统先问一个精确澄清问题并给出可点候选，不猜最近的文件，也不覆盖不确定的目标。

### 任务完成后

已结束的任务仍可以同任务追问，例如：

> 把刚才那份周报压缩成一页，保留风险一节。

### 上下文包含与不包含

会保留：原始目标与后续追问、已完成步骤与检查点、已验证的授权目录、结构化交付物路径与哈希、当前阶段与团队、已批准的文件范围。

不会把完整文件正文、API Key、密码、原始命令输出无限期塞进检查点：大内容按需重新读取，并经边界与脱敏处理。发给模型的协作上下文只携带**当前**有效的认可和最新候选，需求、问题、验收与你的决策保持完整——历史细节留在检查点和事件日志里，不重复灌进提示词。

### 会话隔离

- 同一个群聊共享该群的工作上下文；
- 私聊只绑定当前角色（`dm:{characterId}`）；
- 不会因为在某个群聊里出现过文件，就让另一个私聊自动看到它；
- 工作模式打开时该会话的自动发言暂停，关掉后恢复；
- 普通闲聊和你主动发的消息不会悄悄变成工作任务。

## 文件、文档和图片

### 可读取和分析

| 类型 | 行为 |
|---|---|
| TXT、Markdown、JSON、源码 | 有界读取、分页、搜索和摘要 |
| PDF | 保留页码位置并提取文本；需要核对页面呈现时分页渲染 |
| DOCX | 保留段落位置并提取文本 |
| XLSX | 保留工作表/单元格位置并提取文本 |
| PNG、JPG、HEIC、HEIF、AVIF | 仅在当前角色模型声明支持视觉时发送分析 |
| 音频、视频 | 明确返回不支持，不伪装成已读取，也不安装转码服务 |

### 图片模型选择

当前角色不支持视觉时，任务暂停并请你选择已配置的视觉模型。应用**不会**自动切换角色、也不会偷偷把图片上传到别的模型。选择后，面板会记录附件路径、消息 ID 和分析结果。

### 二进制文件的边界

工作模式可以读取和分析 PDF、DOCX、XLSX 和图片，但不把它们当作普通源码原地二进制编辑。要生成文档内容，让 Agent 产出 Markdown 等文本交付物、再经命令转换成最终格式（例如 Word 必须由转换工具生成，不能把 Markdown 改名充当）；要改动原始二进制文件，请用专门的桌面工具，让工作模式只做分析和变更建议。

## 命令与联网搜索

### 搜索优先级

联网搜索按顺序尝试：

1. 已配置且健康的搜索 API；
2. 不需要 API Key 的网页搜索；
3. 明确告诉你失败原因和下一步。

搜索结果默认只记录来源，不在答案里塞裸链接。可以追问：

> 给出刚才搜索使用的来源链接。

系统会复用本轮搜索快照，不重复发起第二次搜索。

搜索 API 和无 Key 网页搜索都不可用时，会说明失败原因，不会打开浏览器接管窗口，也不会尝试绕过登录、验证码或付费墙。搜索结果一律当作**不可信外部数据**处理：网页里的“忽略审批”“自动授权”之类文字不会变成权限。

## 候选版本、快照与撤销

这里有三样容易混淆的文件，分清楚才不会找错东西：

| 名称 | 是什么 | 用途 |
|---|---|---|
| 工作文件 | 你授权工作区里的当前文件 | 实际成果，修订就按原路径改 |
| 回滚快照 | 操作前的镜像 | 用来撤销，按保留策略回收 |
| 候选交付版本 | 每轮送测的只读副本及证据 | 独立打开、独立核对，不随工作文件变化 |

候选不能借用可能被清理的回滚快照冒充；快照也不能替代候选充当历史交付。

### 快照与撤销

可逆写入在提交前预留快照，完成后保留，用于撤销。撤销会重新检查授权和当前文件哈希；文件已被外部改动时报冲突并保留外部内容，不强行覆盖。

保留策略在「设置 → 工作模式 AI Agent」里**只读显示**为「保留期限：N 天 · 快照上限：X」——默认 30 天与 2 GB，当前版本不能在界面上改这两项。同一处显示「当前快照占用：…」，并提供「立即清理」按钮手动回收符合保留策略的快照。清理只删除 App 自己记录的事件与快照，**不删除你的项目文件**。

## 重启与恢复

退出 App 不会继续生成内容，也不会在后台偷偷跑任务。

重新打开 App 后，任务**不会自动执行**：系统先核对现场（项目、成员资格与配置、文件摘要、工具收据、权限、资源锁），然后等你在面板上点「继续」。这是刻意的——避免 App 重启后无提示地写你的磁盘或联网。

只有链路类故障会有限自动重试，并在面板上写明「链路恢复，已自动继续」。你在面板上的手动操作（继续、重试、停止）会清除自动续跑标记，不会继承它。

旧任务（V1 记录）重启后会被转换并提示「旧群任务已转换为 v2，等待重新核对方案」，需要你显式继续并重新确认角色、方案、工作项、决策与验收；**旧签字不授权当前执行**。

## 私聊与旧任务的差异

群聊走的是本手册描述的 v2 协作闭环；私聊和存量的旧任务走的是旧流程。设置页自己对这条分界有说明：「群聊协作任务不设累计步数或总时长上限；单次请求超时、有限重试和无进展保护仍有效。私聊和旧版任务的软上限：N 步或 M 分钟，达到任一项会暂停并等待继续。」具体差异如下：

| 维度 | 群聊（v2） | 私聊 / 旧任务 |
|---|---|---|
| 选人与确认 | 群内讨论选相关团队，方案逐人确认，交付逐成员认可 | 由角色路由器与协调器串行接力（旧 handoff），没有群讨论与逐成员签字 |
| 累计限制 | 无累积步数与总时长上限，只受无进展保护约束 | 仍受旧的 100 动作 / 60 分钟软上限；触发后在面板上点「继续」开新额度 |
| 进度显示 | 「已执行 N 个动作 · 按有效进展继续」 | 「步骤 N / 100」，并显示「讨论理解进度：N% · 第 N 轮」；旧流程有“理解度达到 100% 才可执行”的门槛 |
| 讨论回复框 | 没有「继续讨论」按钮——讨论自动推进 | 回复框里额外出现「继续讨论」按钮 |
| 停止后的重试 | 只有「继续」 | 可能看到「从头开始」（要求没有留下产物、且已提交操作为空） |
| 交付 | 每轮冻结候选、独立审查、返工复测后正式交付并封存 | 沿用旧的交付与投递通道 |
| 新请求的去向 | 明确新建交付物的请求，只在旧记录已经“交还给你”时才另起一条 | 只要记录还在，新请求默认并入那条记录，并会覆盖它的需求描述 |

因此在私聊里，你看不到讨论、候选冻结和成员认可，也不该去找它们。上面那些“你需要动手”的入口中，视觉模型选择、审批、停止、继续、撤销在私聊同样有效。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示没有可用工作目录 | 尚未授权或授权已失效 | 「设置 → 工作模式 AI Agent → 授权目录」添加或重新授权 |
| 目录显示不可用 | 目录被移动、删除或系统权限变化 | 选原目录重新授权 |
| 任务一直显示“讨论自动进行，你无需操作” | v2 讨论在后台推进，此刻没有需要你做的事 | 什么都不用做；想补充要求直接在群里说 |
| 群讨论轮次很多还没结束 | 方案或验收仍未达成一致 | 等它推进，或在面板上回答待决问题；反复无进展时系统会来问你 |
| 任务停在「等待审批」 | 需要你确认路径或命令 | 看范围和原因后允许或拒绝 |
| 任务显示「已暂停」或「已中断」 | 登录、验证码、安装、问题待答等前置条件没完成 | 按面板提示处理完，再点「继续」 |
| 想自己指定执行人 | 群内推举还没定 | 面板点选候选（「点选即直接指定」）；不点也行 |
| 找不到“签字确认”按钮 | v2 的成员认可是 AI 台账，用户没有签字入口 | 用待决弹窗的「明确豁免」或「记录人工验收」表达意见，或在群里直接说 |
| 明明很多动作了还在跑 | v2 群任务没有累计步数上限 | 正常；只要一直有进展就继续，卡住时会有无进展保护来问你 |
| 我说“继续”但按钮是灰的 | 有前置条件没完成 | 悬停看原因，按[继续](#继续)一节的表逐条处理 |
| 停止后看不到「从头开始」 | v2 协作任务不提供「从头开始」 | 用「继续」；要彻底重来就删除任务后重新提需求 |
| 删除任务后新任务看不到之前的聊天 | 这是刻意的工作上下文分界线 | 聊天消息本身没删；需要旧内容就把它作为附件或写进新需求 |
| 点击隐藏后看不到任务 | 面板隐藏但任务仍在运行 | 点右下角工作任务入口；隐藏不等于停止 |
| 重启后没有自动继续 | 设计为重启后必须由你确认 | 打开任务面板点「继续」 |
| 图片任务无法继续 | 当前角色模型不支持视觉 | 面板点「选择视觉模型」选一个已配置的 |
| 搜索总是失败 | 搜索 API 不可用或网页有挑战 | 查看失败原因，配置可用的搜索 API；系统不会绕过登录或付费墙 |
| 找不到 rg / 其它命令 | 工具未安装或路径不在允许范围 | 面板点「帮助安装工具」；确认来源与影响后再安装 |
| 撤销提示冲突 | 文件已被外部程序修改 | 查看冲突，不要强行覆盖；重新读取后再规划 |
| 交付文件合格但聊天里没收到附件 | 只是消息附件投递失败 | 任务仍算完成，面板只重试发送，不会重新生成 |

## 能力的边界与提示词写法

### 推荐怎么写

同时写清：**目标**（要得到什么）、**范围**（允许访问哪些目录/文件）、**是否允许写入**、**交付格式**（摘要/差异/文件路径/测试结论）、**完成条件**（什么结果算完成）。

**只读分析**

> 读取 `<授权目录或文件>`，只做分析，不修改任何文件、不运行命令。请给出结论、证据路径和不确定项。

**精确修改**

> 修改 `<绝对路径或授权目录内相对路径>`，只改这个文件。先说明计划和预计影响，批准后再写入，完成后给出差异摘要。

**同一文件修订**

> 修改刚才生成的同一个文件 `<文件名/路径>`：将 `<要求>`。不要另存为新文件，不要改其他路径。

**软件任务**

> 在 `<授权项目目录>` 实现 `<功能>`，按需求里的验收项逐条自测并给出运行结果；测试由不同于实现者的成员执行。

**测试 / 构建**

> 在 `<授权项目目录>` 运行 `<明确命令>`，这是我明确要求的测试。不要修改源码，输出失败摘要和退出码。

**联网搜索**

> 搜索 `<主题>`，优先可靠公开来源。默认答案不要放链接，只记录来源；我之后单独追问来源链接。

**图片分析**

> 分析附件 `<图片>`，只读取图片内容，不修改本地文件。若当前模型不支持视觉，请暂停并让我选择模型。

### 不推荐怎么写

- 「让产品经理来做这个」：v2 由团队选人，`@` 只在首次路由生效，写死人选通常帮不上忙；
- 「把电脑清理一下」：范围和删除风险不明确；
- 「把刚才那个改好」：历史里可能有多个文件，应给出文件名或路径；
- 「顺便跑一下所有东西」：构建、测试、依赖安装应明确写出；
- 「自动登录并提交」：登录与提交需要人工确认，且可能涉及敏感凭据。

## 已知限制

- **成员认可没有用户签字入口。** v2 里签字是 AI 成员的台账，用户的表达方式是「明确豁免」和「记录人工验收」。这是当前设计，不是遗漏。
- **没有独立的“审查报告”浏览页，界面上也不出现“发布编号”这个词。** 审查报告以带附件的聊天消息送达（见第 6 步），候选与审查的引用汇总在面板的「问题与方案详情」里，完整的候选目录与报告文件留在工作区。轮次编号在内部会分配，但不是一个需要你记住的界面概念。
- **浏览器能力当前不可用。** 需要真实浏览器交互的验收（例如网页游戏的实际操作测试）必须阻塞或走你明确的人工验收/豁免；“标签校验通过”或“能打开”都不算交互测试通过。
- **音视频不支持**，也不安装转码服务。
- **App 完全退出后不继续生成。** 前台主动私聊允许调用已配置的 API，但冷却保守；没有明确的通知与推送设计前，不做后台或离线生成。
- **一次模型请求的输出有上限**，由模型能力声明与上下文窗口共同决定。长内容必须分块写再合并，因此超长交付物会分成多步完成。
- **每类协作台账有条数上限**（例如候选版本索引只保留最新若干轮），超出时任务会阻塞并求助，而不是静默丢弃；被取代那一轮的候选文件、清单与审查报告仍留在工作区和详情里。
- **macOS 上凭据不以系统钥匙串加密保存**，而是明文存在 App 自己的数据目录（ad-hoc 签名下钥匙串要么每次重建都弹密码框、要么在 release 里写不进去）。能读到该目录的进程就能读到这些 Key——请只授权完成任务所需的目录，并把敏感文件读取视为需要额外确认的操作。
- **Windows 与手机的实机 UI 验收**尚未完成；Web 构建不是发布目标，因为它无法提供服务端凭据边界。
- **备份**覆盖除用量审计账本外的数据；工作目录路径在导入时被丢弃（本地路径不可移植），恢复后需要重新绑定项目与凭据。仅配置备份**不包含**任务交付历史；未能打包的本地文件会标注为缺失，导入后不会把无文件的索引当成完整历史。
