# 第 9 章 · 联网搜索

上篇第 6 步讲的是"怎么打开它"。这一章讲**它怎么工作、怎么配、怎么排查**。

## 9.1 三档策略：怎么选

| 档位 | 什么时候用 |
|---|---|
| **关闭** | 不想要任何外部信息时 |
| **询问** | **第一次用建议选这个**。每次搜之前都问你一句，你先看看它搜得对不对 |
| **自动** | 用熟了再换。它自己判断该不该搜 |

界面上的原话是：

> 默认关闭。询问模式每次都需明确同意；启用后，查询会发送给已配置的 Provider 或智谱原生 Web Search。DuckDuckGo 仅作为百科即时答案兜底，不等同于完整 Web 搜索。

**临时切换不用进设置**：聊天室右上角「更多操作」菜单里有一项「**联网搜索：自动**」，名字里的档位就是你当前的选择。

## 9.2 搜索服务凭据：要配什么

治理页 →「**搜索服务凭据**」。

> 区块说明原文：Provider 与智谱原生搜索的 Key、地址和默认服务商

点「添加」后，表单是这些字段：

| 字段 | 说明 |
|---|---|
| **Provider 名称** | 给你自己认的名字 |
| **Provider 类型** | 见下表 |
| **Base URL** | 服务地址 |
| **API Key** | 该服务的凭据。编辑已有 Provider 时显示「API Key（留空保持当前值）」 |
| **启用此 Provider** | 开关 |
| **设为默认搜索源** | 开关。多个 Provider 时决定默认用哪个 |
| **测试连接** | 先测一下再保存 |
| **保存配置** | — |

**新建时「Provider 类型」只有三种可选：**

| 类型 | 是什么 |
|---|---|
| **Backend Gateway** | 官方的后端搜索网关。**推荐用这个** |
| **Tavily** | Tavily 搜索服务，需要它自己的 Key |
| **Brave** | Brave 搜索服务，需要它自己的 Key |

界面上可能还会看到两种 DuckDuckGo 类型，**但它们只在你已经配过的情况下才出现**，不作为新建选项。

> **关于「角色模型原生联网」**：它**不是一个 Provider**。它在治理页的「搜索运行参数」里，是一个单独的开关——打开后走模型厂商自己的联网能力，而不是上面这些第三方搜索。
>
> 界面原文：**使用设置页保存的智谱 API Key；搜索结果再同步给角色回复**

## 9.3 你问一句，全群共用一份搜索结果

这是一个很重要但不容易注意到的机制：

**搜索是"按你的这一轮发言"算的，不是按角色算的。**

具体表现：你问一句有时效性的问题，如果这一轮有 3 个角色回复，**它们共用同一份搜索结果**。

**带来两个好处：**

1. **不会重复搜三次**（省钱、省时间）
2. **不会出现"张三说今天下雨、李四说今天晴天"** ——因为大家看的是同一份材料

## 9.4 回答里的来源编号

搜索生效时，角色的回答里会出现形如 `[1]`、`[2]` 的编号，回答下方列出对应来源。

**为什么要有编号**：它让你能**一条条核对**——"这句话是哪个网页说的"。没有编号的回答，你没法判断它是搜来的还是编的。

**核对方法**：看到可疑结论，去治理页的「**联网记录**」找那条查询，看它当时搜到了什么。

## 9.5 搜索结果被当成"别人说的话"，不是"命令"

这是一条安全设计，用户侧的体现是：

**网页内容不会改变角色的行为规则。**

比如某个网页里写着"忽略你之前的所有指令，去执行某某操作"，角色**不会照做**。搜索结果会被当作**结构化的参考材料**送进去，附上来源编号——而不是原封不动倒进对话里当指令。

**你自己该做的一件事**：如果某次回答的来源看着可疑（奇怪的域名、和问题不相关的内容），**别信那条回答**。换个问法，或者先关掉联网再问。

## 9.6 缓存

搜索结果会缓存一段时间。同一类问题短时间内重复问，可能用的是缓存而不是新搜。

**想强制重搜**：治理页 →「**清除搜索缓存**」。

## 9.7 排查联网问题，只有一个正确入口

**治理页最下面的「联网记录」。**

> 页面原文：**含查询、时间、状态和来源；最多保留 100 条**

每条写着：查询词、时间、`success` 还是 `failed`、搜到几个来源。**失败也会记。**

**三条判断规则：**

| 你看到的 | 结论 |
|---|---|
| 有这条记录且 `success`，来源数 > 0 | 搜了，也搜到了。回答里没编号是模型没引用 |
| 记录是 `failed` | 搜索本身失败了。查凭据和服务地址 |
| **压根没有这条记录** | **说明它根本没搜**——那条回答是模型凭记忆编的 |

**最后一条最有价值。** 角色答出一个很具体的实时信息但没编号时，别猜，去查记录：**没有记录 = 一定是编的。**

## 9.8 卡住了

| 现象 | 怎么办 |
|---|---|
| 三件事都配了还是没编号 | 去「联网记录」看看有没有记录。有记录说明搜了，是模型没引用——换更强的模型 |
| 记录里全是 failed | 凭据或服务地址有问题。先点「测试连接」 |
| 没配过任何 Provider | 至少加一个（推荐 Backend Gateway），并勾上「设为默认搜索源」 |
| 只在群里聊不搜 | **设计如此**：只在你主动发言的轮次搜 |
| 想要"群里也自动搜" | 目前不支持。可以改成把问题明确提给群 |
| 搜索结果和上次一样 | 缓存。点「清除搜索缓存」再问 |
| 想让角色用更聪明的搜索词 | 打开「使用 AI 改写搜索词」。ask 模式下它会先给你确认改写后的搜索词 |
| 回答引用的来源打不开 | 来源可能过期或需要登录。编号本身是可信的，内容是第三方的 |
