# 第 4 章 · 圆桌会议

## 4.1 它和普通群聊的区别

| | 普通群聊 | 圆桌会议 |
|---|---|---|
| 谁说话 | 伴伴**挑** 1~3 个角色接话 | **全员依次发言**，一个不落 |
| 怎么决定谁说 | 按 `@`、最近发言、关系、话题契合度算出来 | 不算，排队 |
| 适合什么 | 日常闲聊 | 需要**所有人都表态**的事 |

一句话：普通群聊是"谁想接话谁接"，圆桌会议是"挨个发言"。

## 4.2 怎么开

聊天室输入区上方那排胶囊的**第四个**（圆桌图标）。悬停提示写着：

> 开启圆桌会议模式（用户事件联网搜索后由群成员讨论）

**这个开关是跟着群走的。** 在这个群开了，别的群不受影响；你离开再回来，它还是开的。

## 4.3 开会时会多出一个"不发言的"成员

开启圆桌后，群里会出现一位特殊成员：**新闻角色**，身份写着「**圆桌会议联网搜索助手**」。

它的职责是**给所有人备料，本人不发言**：

> 你提出话题 → 它先去搜一遍 → 把结果交给群成员 → 群成员基于这份材料依次讨论

**开圆桌之前顺手检查一下它**：在群成员面板里看这一行。如果写着「**未配置 API**」，那它没法完成备料这一步——先去给它绑一份可用的模型配置。

## 4.4 什么时候值得开

**适合：**

- 你想听**所有人**的看法，而不是谁抢到话谁先说
- 要做个决策，希望每个人的立场都摆到台面上
- 话题本身需要多角度（方案评估、复盘、头脑风暴）

**不适合：**

- 人多的时候 —— **人越多越慢越贵**，因为全员发言意味着每个角色都要独立请求一次
- 你只是想要一个快速答案 —— 普通群聊更快

## 4.5 和「自动聊天」的关系

圆桌会议管的是**你怎么发言时谁来接**，自动聊天管的是**没人说话时群要不要自己聊**。两者互不冲突，可以同时开或分别关。

## 4.6 卡住了

| 现象 | 怎么办 |
|---|---|
| 一轮要等很久 | 正常。全员发言 = 至少 N 次模型请求。人多的群建议别常开 |
| 某个人一直不发言 | 群成员面板看它的状态：可能写着「未配置 API」，也可能被**禁言**了（禁言在圆桌里同样生效） |
| 那个"新闻角色"不动 | 检查它有没有绑可用的配置。群成员面板里能看到 |
| 讨论内容很水 | 圆桌只是改变"谁发言"，不改变模型水平。想更深入还是得靠 System Prompt 和更强的模型 |
| 想关掉 | 再点一次那个胶囊。**开关状态会留在那个群里**，下次进来还是关着 |
