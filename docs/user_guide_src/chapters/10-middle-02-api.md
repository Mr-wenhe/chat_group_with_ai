# 第 2 章 · API 配置与模型能力

## 2.1 一份配置包含什么

一份 API 配置 = **地址 + 协议 + 模型名 + Key**。角色绑的是配置，不是 Key，所以多份配置可以复用同一把 Key，也可以给不同角色用不同模型。

配置列表在 **设置 → API KEY 设置 → 「对话」组的「聊天与角色发言」** 里。每张卡片上有三个按钮：

| 按钮 | 作用 |
|---|---|
| **测试** | 直接对已保存的配置打一次真实请求，不用进表单 |
| **编辑** | 打开表单修改 |
| **删除** | 删掉这份配置 |

卡片上显示的 `提供商名 · 协议` 和 `API Key 已保存` 是你的核对线索。

## 2.2 九家提供商 + 四种上游格式

**提供商**决定默认地址和默认协议：

| 提供商 | 内置地址 | 默认协议 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | OpenAI Chat Completions |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI Chat Completions |
| 智谱AI | `https://open.bigmodel.cn/api/paas/v4` | OpenAI Chat Completions |
| Moonshot | `https://api.moonshot.cn/v1` | OpenAI Chat Completions |
| 百度文心 | `https://qianfan.baidubce.com/v2` | OpenAI Chat Completions |
| 讯飞星火 | `https://spark-api-open.xf-yun.com/v1` | OpenAI Chat Completions |
| 商汤 SenseNova | `https://token.sensenova.cn/v1` | OpenAI Chat Completions |
| Oray | `https://ai-api.orayer.com/v1` | **Anthropic Messages（原生）** |
| 自定义 | 空（自己填） | OpenAI Chat Completions |

**上游格式**（协议）描述的是「对面这个接口按什么规矩说话」，跟厂商名无关。同一家厂商也可能给你不同协议的入口：

| 协议 | 界面说明 | Base URL 例子 |
|---|---|---|
| **Anthropic Messages（原生）** | 请求 `/v1/messages`；使用 `x-api-key` 鉴权 | `https://api.anthropic.com/v1` |
| **OpenAI Chat Completions** | 请求 `/chat/completions`；适用于 OpenAI 兼容接口 | `https://your-api.com/v1` |
| **OpenAI Responses API** | 请求 `/responses`；适用于实现 Responses API 的接口 | `https://api.openai.com/v1` |
| **Gemini Native generateContent** | 请求 `:generateContent`；适用于 Gemini Native 接口 | `https://generativelanguage.googleapis.com/v1beta` |

> **选哪个？** 用内置厂商时它已经替你选好了，别动。只有选「自定义」时需要你自己判断——**看你拿到的文档写的是哪个接口路径**。

> **Oray 是个特例**：它只提供 Anthropic 原生协议，模型名要带上游命名空间（形如 `deepseek/deepseek-flash`）。所以它的默认协议和别家不一样。

## 2.3 表单里的三个联动行为

这三条是"为什么我的输入被改了"的答案：

**① 选完提供商，自动填地址和协议**

不是只填地址——**协议也会被换成那家的默认值**。

**② 换提供商，模型名被清空**

这是防你拿 A 家选的模型名去请求 B 家。换完厂商记得回头重填模型名。

**③ 模型名永远不预填**

这是刻意的：厂商的模型清单变得很快，预填一个已下线的名字，等于让你存下一份跑不通的配置。

拿模型名有两个办法：点输入框右边的**云朵图标**从你的账号里拉真实清单；或者照官方文档手输。

## 2.4 「模型能力」这五个值，决定它能干什么

![API 配置表单](images/06-api-config-form.jpg)

*图 44：表单下半部分就是模型能力。它按「提供商 + 模型名」保存，同一个模型的所有配置共用。*

| 项 | 界面原文 | 实际影响 |
|---|---|---|
| **流式** | 支持逐字输出。**关掉后工作模式无法启动** | 工作模式硬依赖它 |
| **视觉** | 能否读图片附件。关掉后带图任务会暂停并要求换模型 | 影响你能不能发图给 AI 看 |
| **工具** | 能否调用工具。**关掉后工作模式无法启动** | 工作模式硬依赖它 |
| **上下文 Token** | 一次请求可用的上下文窗口；工作模式按最多一半窗口预留输出空间 | 决定它能"记住"多长的上下文 |
| **最大输出 Token** | 模型声明的输出能力；用于预算估算及必要协议的输出参数 | 决定单次能产出多长的内容 |

**两件事必须知道：**

**① 输出预留会挤占输入空间。** 工作模式按模型声明的最大输出与上下文一半的较小值，预留输出空间供输入预算和费用预检使用；这不是所有协议的实际生成上限。

**② 长内容仍可能被上游截断。** 工作模式对 OpenAI Chat Completions、OpenAI Responses、Gemini 不发送客户端输出上限参数；Anthropic Messages 按协议要求仍发送 `max_tokens`。服务商和模型自身的上限仍然有效。检测到截断后会改用分块写入，再合并或转换成交付物，不能承诺无限生成。

内置模型有现成的声明值，一般不用动。改坏了点「**恢复内置默认**」还原。

### 工作模式缓存优化（按配置单独开关）

配置表单「模型能力」上面有一行开关：

> **工作模式缓存优化** — 仅在确认此接口支持后开启。缓存写入可能单独计费；命中量以上游返回为准。关闭后不发送额外缓存参数。

**默认是关的，旧配置升级上来也是关的。** 这不是"打开就省钱"的开关，前提是你**已经确认这条线路支持缓存**。

| 项目 | 说明 |
|---|---|
| **管什么** | 只影响工作模式的讨论、执行与上下文压缩；普通聊天不发任何额外缓存参数 |
| **按协议怎么实现** | Anthropic 原生协议在固定的系统内容末尾标一个 5 分钟缓存；OpenAI 兼容协议带一个稳定的缓存键；Gemini 原生**不创建**显式缓存对象 |
| **会不会偷偷保活** | 不会。不会自动预热、不会延长缓存期限 |
| **被服务商拒绝怎么办** | 直接报错给你看。**不会**自动把参数关掉再重发一次——那样你就不知道自己开了什么 |

> ⚠️ **两句话别记反**：
>
> 1. **缓存写入可能单独计费**，命中量只认上游返回的数字。页面上的命中率不是省钱承诺。
> 2. 中转服务返回的用量**不等于厂商账单**。没拿到实报时，伴伴不会替你估算缓存省了多少钱。

改完记得保存配置。开关跟着这份配置走，导出配置包时也会带上它。

## 2.5 Key 存在哪（必读）

密钥设置页最上面那张卡片的原文：

> 所有 API Key 都只保存在本机：macOS 写入应用数据目录内的本地库（**明文，不经系统钥匙串**），其余平台写入系统安全存储（钥匙串 / Keystore）。都不会出现在备份、导出文件或聊天记录里；换机或重装后需要重新填写。

拆成两句人话：

**✅ 好消息**：Key 不会跟着备份和导出走。你把备份文件发给别人是安全的。

**⚠️ macOS 上要留意**：Key 是**明文**存的，没有系统级加密兜底。能读到你这台电脑用户数据目录的程序，就能读到这些 Key。这是刻意取舍——避开钥匙串在每次重建后反复弹密码框的问题。安全性要求高的场合，请以「这台电脑别借给不信任的人」为前提。

> **升级提示**：旧版本把 Key 存在 macOS 钥匙串里。这些 Key **不会自动迁移**，升级后需要重新填一次。

## 2.6 换电脑：导入 / 导出 API KEY

密钥设置页里的「**批量配置**」：

| 功能 | 界面原文 |
|---|---|
| **导出 API KEY** | 把本机已配置的 API Key 打成一串授权码，在其它客户端导入即可 |
| **导入 API KEY** | 粘贴分发方给你的加密授权码，解析后会**先列出将新增 / 覆盖 / 跳过哪些条目，确认之后才写入** |

**导入不会闷头改你的配置**——它会先摊开给你看，确认了才动。装新机时用这个，比一份份重填快得多。

## 2.7 卡住了

| 现象 | 怎么办 |
|---|---|
| 测试连接一直转圈然后失败 | 有的线路对连续请求做了限制，停一会再试；也可能是网络到不了那家服务商 |
| 提示 401 / 鉴权失败 | Key 错了、失效了，或这把 Key 没开通你填的那个模型 |
| 提示 404 | 协议和 Base URL 不配套。OpenAI 兼容接口地址通常带 `/v1` |
| 提示被重定向 | 你填的地址会跳转。**改成跳转后的最终地址**——伴伴不会让带 Key 的请求跟着跳 |
| 编辑配置时 Key 那栏是空的 | 正常。留空 = 用原来那把；填新的 = 换 Key。Key 不会被回填显示 |
| 加了新模型但角色还用旧的 | 角色是绑在**配置**上的。换模型后在角色列表点那一行的模型名切换 |
| 想让一批角色换模型 | 角色列表顶部的「批量替换」，只在你有多份配置时出现 |
| 模型能力改乱了 | 表单里点「恢复内置默认」 |
