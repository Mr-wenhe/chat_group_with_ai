# 第 10 章 · 工作模式

上篇第 7 步讲的是"怎么让它干活"。这一章讲的是**它到底怎么干活的**，以及出问题时你能做什么。

## 10.1 开关是"每个会话一个"

工作模式**按会话独立开关**。在 A 群打开，不影响 B 群；离开再回来，它还是开的。

**打开之后有两件事同时变化：**

1. **你发的非空消息不再触发闲聊轮次**，而是变成一条工作任务
2. **群里的自动聊天停止**——界面上会显示「ⓘ 工作模式中，自动发言已暂停」

关掉之后自动发言恢复。

## 10.2 一条任务会经历什么

工作的流程是**固定的几个阶段**，不是让模型自由发挥：

```
建任务 → 用户确认本版需求
  → 讨论阶段（选团队 → 查证未决问题 → 形成方案 → 逐成员认可）
  → 指定执行人
  → 制作（做出来 → 冻结候选 → 等你选择）
  → 可完成：按用户确认直接交付；或继续测试：独立审查 → 返工复测 → 逐成员认可
  → 交付（产物 + 文件摘要校验）
```

![讨论阶段](images/44-work-group-discussion.jpg)

*图 1：讨论阶段。方案和分工在群里谈拢之前，不会进入制作。*

**几个值得知道的点：**

- **讨论和执行是分开的**。先在群里把方案和分工谈拢，谈不拢就不进入制作。
- **候选会被"冻结"**。做出来的东西先冻结成一个版本，之后可以回看每个候选版本。
- **选择「继续测试」后，审查是独立的另一轮**；选择「可完成」则直接交付，并明确未测试。
- **交付前会核对真实文件摘要**。文件内容对不上，不算交付成功。

### 开始前确认需求卡

新群任务先显示「待你确认」需求卡：列明目标、负责人、保存位置、交付文件、功能验收、默认建议和仍需你决定的问题。核对后点击「确认本版需求」，或在群里单独回复「确认」「接受」「同意」。带附件或包含新要求的消息会按补充输入处理，不作为简单确认。

确认前不会启动群讨论、制作或写入产物。补充或纠正要求会更新需求版本，旧卡不能确认新版内容；打开最新任务状态再处理。私聊沿用原有任务流程。

### 本轮成果冻结后，由你选择

弹窗标题是「本轮成果已冻结，是否可完成？」。成果附件会先发到对话中，可先预览，再决定：

| 按钮 | 后续行为 |
|---|---|
| **可完成** | 按你的确认直接交付并完结，**不声称测试通过** |
| **继续测试** | 进入测试与独立审查，发现问题后返工复测，成员认可后正式交付 |
| **补充需求** | 保持暂停，补充文字、文件或图片 |

关闭弹窗不会自动替你作决定；可从任务面板「确认本轮成果」重新打开。每次确认只对当前需求、团队和冻结成果有效，修改后的新成果需要重新确认。单文件交付直接提供约定文件，不一定打包成 ZIP。

### 执行途中补充需求

讨论、制作或测试期间，可点任务面板「补充需求／暂停」。当前动作结束后停在安全检查点，不会强行中断正在落盘的动作。

在「补充需求」窗口输入文字，或使用「添加文件或图片」「粘贴」。点击「提交补充并保持暂停」保存；「保持暂停」关闭窗口。**提交和关闭都不会自动恢复执行**，需确认更新后的需求或显式继续。

补充内容会保留在对话及任务队列中；连续修改同一文件时请明确说出目标，避免被理解为另建文件。

## 10.3 谁被选中来干这个活

不指定的话，伴伴会从**群成员里挑一个本职对口的**。

它怎么判断"对口"：

1. **职业/身份**（角色的「角色」那一栏，比如「前端开发」「产品经理」）
2. **技能**（角色表单里「行动能力」那块配的技能）

**两条值得知道的规则：**

- **群里只有一个人本职合格时，直接指定它**，跳过选人这一步。讨论仍会确认方案和逐人认可。
- **你 `@` 某人只是"征求意见"时，它不会自动指定人。** 因为你只是想听听意见，不是要派活。

**不满意谁来干，你自己点。** 任务面板里有「**指定最终执行人**」——点开后是候选角色列表，每个候选旁边写着它凭什么有资格。选一个确认即可。

> **注意**：`@角色名` 只在任务**第一次派活**时有效。任务一旦进入讨论，之后你发的消息只是"补充要求"，不会再重跑派活。**想自己指定，用面板上的那个按钮。**

## 10.4 面板上的按钮，完整对照

| 按钮 | 什么时候出现 | 点了会怎样 |
|---|---|---|
| **回到对话** | 常驻 | 收起面板去聊天，**任务继续跑** |
| **稍后处理** | 等你审批时 | 先不管，任务停在原地等你。提醒一直在 |
| **批准** | 等你审批时 | 同意这一步 |
| **拒绝** | 等你审批时 | 群协作禁止本次操作并尝试安全替代；私聊或旧流程暂停 |
| **无撤销执行** | 需要你确认不可撤销动作时 | 明确承担后果后执行 |
| **允许本次范围** | 任务变更审批 | 只允许这一次这个范围 |
| **拒绝本次操作 / 拒绝并暂停** | 任务变更审批 | 以当前弹窗说明为准；群协作的拒绝不等于停止整个任务 |
| **授权目录** | 需要新目录时 | 打开授权流程 |
| **确认执行人** | 路由出来时 | 确认或改派 |
| **从头开始 / 重试** | 满足相应恢复条件时 | 停止的任务用「继续」；群协作不提供「从头开始」，见 10.5 |
| **确认本版需求** | 待确认需求时 | 接受当前需求版本后进入讨论 |
| **补充需求／暂停** | 群协作进行中 | 在安全停点暂停，补充后仍保持暂停 |
| **确认本轮成果** | 当前冻结成果待选择时 | 打开直接交付、继续测试或补充需求的选择窗 |
| **重新提交命令审批** | 有可重新申请的命令且任务已停下时 | 选择命令后点击「继续」，重新走审批，**不直接执行** |
| **停止** | 任务进行中 | 停下，**可以继续** |
| **继续** | 停止之后 | 从停下的地方接着跑 |
| **撤销** | 有快照时 | 把任务改过的文件回滚 |
| **查看冲突** | 文件冲突时 | 看是哪个文件撞了 |
| **帮助安装工具** | 缺工具时 | 走安装流程 |
| **选择视觉模型** | 需要用图像时 | 挑一个支持看图的模型 |

**面板右上角两个图标**：时钟 = **历史任务**；箭头 = 收起面板。

## 10.5 停止 / 继续 / 重试 / 从头开始，到底差在哪

**这一节最值得记。**

| 动作 | 做什么 | 已经干过的活 |
|---|---|---|
| **停止** | 停下当前任务。**这是"可以继续"的终态** | 检查点全保留 |
| **继续** | 从停下的地方接着跑 | 先核对检查点和文件状态，再接着来 |
| **重试** | 让模型重做**失败的那一步** | 有提交收据或可核对后置条件的写入会跳过；无法确认的副作用先求助 |
| **从头开始** | 重新走一遍 | 会重来。**v2 协作任务不提供这个** |
| **撤销** | 回滚文件改动到任务开始前 | 文件回到原样，任务记录还在 |

**两个容易困惑的地方：**

**① 「停止」不是"结束了就没了"。** 你停下来，随时可以点「继续」接着跑，它记得自己做到哪了。

**② 「从头开始」在群协作任务里根本不出现。** 因为那会清空整块协作记录（方案、工作项、认可），代价太大。用户主动停止后使用「继续」；可重试的失败使用「重试」。按钮只在满足相应条件时出现。

## 10.6 同时能跑几个

**最多 2 个任务同时执行。**

多出来的会排队，等前面腾出位置再开始。这是全局的限制，不是你当前页面的限制——**你的任务在你切到别的群之后仍然在跑。**

## 10.7 两种任务的时间限制不一样

| 任务类型 | 累计步数与总时长 |
|---|---|
| **群聊协作任务** | **不设上限**（单次请求超时、有限重试、无进展保护仍然有效） |
| **私聊任务和旧版任务** | 软上限 **100 步或 60 分钟**，达到任一项会暂停并等你继续 |

> 界面原文：「群聊协作任务不设累计步数与总时长上限；单次请求超时、有限重试和无进展保护仍有效。私聊和旧版任务的软上限：100 步或 60 分钟，达到任一项会暂停并等待继续。」

**"无进展保护"是什么**：如果它连续几步都在原地打转（没有任何实际进展），会停下来向你提问，而不是一直转下去烧钱。

## 10.8 三个保护机制，看到别慌

| 你会看到 | 它在保护什么 |
|---|---|
| 「本次变更不在本任务已批准的路径范围内，需要先确认具体影响范围」 | 防止它偷偷改你没批的文件 |
| 停下来问「无法确认上一步是否已完成」 | 宁可问你，也不盲目重放——避免把你的文件改两遍 |
| 首字节长时间没动静后自动重试一次 | 上游"接了请求但不吐字"时提前放弃，不干等到超时 |

**第一条特别值得留意**：你在任务进行中追加了新要求，如果新要求会让它动到**新的文件或目录**，它会重新找你确认。这是设计，不是找麻烦。

## 10.9 私聊里的工作模式

私聊也能开工作模式，但有几处不一样：

| | 群聊 | 私聊 |
|---|---|---|
| 谁执行 | 群里挑或你指定 | **固定就是私聊的那个人** |
| 讨论阶段 | 有，多人讨论 | 简化 |
| 任务记录 | 终态后新需求另起一条 | 修订通常沿用旧任务；明确新建交付物且旧任务已交还时另起一条 |
| 步数/时长上限 | 不设 | 100 步 / 60 分钟 |

**连续修改**通常沿用同一条任务记录，并覆盖你明确指定的原文件；明确新建文件时，若旧任务已结束，或已中断且没有排队输入、也不在等你回答，则可以另建任务。执行动态默认收敛到当前运行段，更早的内容可展开查看。

**删除任务与隐藏标签不同**：隐藏只收起标签，记录仍在；删除会移除任务及公开事件日志，已生成文件和聊天消息保留。该会话后续工作任务不会再自动带入删除前的工作聊天上下文；普通闲聊不受这条分界影响。

## 10.10 停止之后，已经做出来的东西还在吗

**在。**

- 已写出的文件**不会因为任务失败或停止而被删**
- 中间产物会**附在聊天消息里**，你可以直接拿走
- 检查点保留着，点「继续」或「重试」从最近的安全点接着跑

**失败消息里会写清四件事**：为什么失败、做到哪一步了、产出的文件在哪、下一步该怎么办。这四样都值得读。

## 10.11 卡住了

| 现象 | 怎么办 |
|---|---|
| 任务不动 | 它在等你——看聊天里的「查看任务」「查看审批」 |
| 一直不开始，也没有提醒 | 面板里看它卡在哪一步；可能就是排在 2 个名额后面等着 |
| 群里没人有资格 | 面板点「指定最终执行人」自己挑一个 |
| 卡在等模型很久 | 看执行动态有没有在动。长时间零动静可以先「停止」再「继续」 |
| 想让它别动文件了 | 点「停止」；关掉工作模式不会停止已在运行的任务 |
| 它改坏了文件 | 点「撤销」（前提是当时建了快照）。审批里写着「可撤销」的就有 |
| 报「无法确认上一步是否已完成」 | **这是保护**。看它列出的信息再决定 |
| 私聊里的任务带着一堆旧历史 | 用面板里的删除真删掉，换新会话干净起步 |
| 任务跑完后想接着改 | 直接说「把刚才那个文件改成…」。它知道你说的是哪个 |


## 10.12 看懂当前进展与用量

群协作面板顶部显示当前阶段、需求版本、候选轮次、负责人、最近进展与下一步，并区分「当前不需要你操作」和「需要你操作」。等待成员回应或收到模型生成活动，只证明请求仍在进行，**不代表方案已采纳、文件已完成或测试已通过**。窗口较矮时部分动态会收起，可放大窗口查看。

点击「用量」打开「当前任务用量」，查看输入、缓存、输出 Token 和请求记录，并可「按运行段和成员展开」。缓存 Token 已包含在输入中，不要重复相加。未知用量、估算用量、价格未知会分别提示；超过当前模型能力上限的历史异常记录从任务统计排除，但原账本保留。没有任务归属的旧记录不会按会话猜测补入，费用以服务商账单为准。

群讨论默认无响应活动时限为 180 秒、单次总时限为 300 秒。收到正文或生成活动后不再按首字节停滞判断，总时限仍有效；失败时看面板原因与恢复入口，不要把等待当作已完成。
