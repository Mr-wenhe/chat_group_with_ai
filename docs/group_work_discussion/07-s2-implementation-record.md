# S2 实施记录：持久讨论状态与执行前门禁

日期：2026-09-11
范围：仅实施 `03-implementation-plan.md` 的 S2；没有实现 S3 的多成员真实讨论调度、模型发言或进度消息，也没有提交或推送。工作区已有 S1 改动全部保留。

## 已完成

1. 新增 `WorkDiscussionState` 纯值对象，使用现有 `AgentTask.executionStateJson` 的 `discussionState` 扩展保存版本、群组、请求版本、协调人、候选/执行人、参与记录、轮次、理解百分比/依据、未决问题、阻碍、决策摘要和产物合同。解析入口对未知版本、非法百分比、缺少门禁字段、非法参与记录、跨群状态和过大文本失败关闭；ready 状态还必须有执行人候选资格和非空理解依据。没有新增 HiveType、枚举或数据库。
2. 群工作输入消费 S1 的结构化路由结果。未选执行人、提及歧义、无合格角色或路由失败时，会建立持久的暂停任务；路由尚未形成合同的失败也使用最小 generic 合同承载等待状态。`characterId` 保持空值，不把临时协调人或候选人伪装成工具执行人。私聊继续沿用固定角色路径，不触发群讨论门禁。
3. `WorkTaskCoordinator` 在提交、调度启动、恢复和公开的讨论状态转换入口检查群组归属、请求版本、合同执行人、讨论阶段、理解度、未决问题、阻碍和角色身份。未达到 `ready + 100% + 无问题/阻碍 + 合同/执行人有效` 时只保存等待状态，不调用 runner；状态达标后仍由生产 runner 复核角色是否属于当前群、处于启用状态、开启 Agentic、模型和凭据可用。
4. 等待讨论只保留会话串行占用，不申请目录或文件资源锁；暂停、停止、取消和协调器重启都清除运行中的临时资源。运行身份校验和任务终态保护使迟到的 runner/讨论回调不能复活已取消任务。
5. `WorkContextSnapshot`/`WorkContextBuilder` 将讨论状态纳入允许列表、任务恢复、上下文压缩和模型摘要保护。压缩可以缩短参与/说明文字，但保留阶段、请求版本、执行人、阻碍、理解百分比和产物合同；已有审批、附件、资源锁和接力元数据仍保留。恢复时以 `executionStateJson` 的讨论标记为权威，压缩摘要只能在没有标记的旧任务上作为回退，避免旧摘要覆盖新版本门禁。
6. 恢复时为缺少讨论扩展的旧未完成记录补写“待讨论”状态，不把旧记录宣称为已讨论；已完成操作、产物和任务字段保留，恢复不会自动回放旧命令。旧记录需要通过新的讨论状态后才可继续。

## 关键兼容决策

- 不修改 `AgentTask` Hive 字段和生成文件，避免旧盒子迁移；空 `characterId` 只作为群任务等待执行人的承载值，实际执行前必须由讨论状态写入真实执行人。
- 未携带扩展的旧任务在正常测试构造/旧调用中仍可被既有协调器提交，避免破坏兼容 API；应用恢复会立即补写待讨论状态并阻止自动继续。新群工作入口始终写入扩展，因此生产任务不会走旧旁路。
- 讨论状态与审批、安装、目录授权保持独立。讨论完成只取得执行资格，工具审批和授权仍需各自的现有检查。
- 同任务追问会提高请求版本并重新生成待讨论状态，避免上一轮的 100% 或旧合同直接覆盖新请求；现有 FIFO 队列仍由唯一协调器拥有。
- 旧的、没有扩展的已完成任务继续保留兼容追问路径；旧未完成任务在恢复时补写待讨论状态。新群任务和带讨论标记的追问不能走旧旁路。

## 验证

新增/扩展测试覆盖：

- 合法待讨论 → 100% ready → runner 启动；99% 拒绝；100% 但未决问题拒绝；过期请求版本拒绝；无执行人等待；跨群状态拒绝。
- 协调器重启后等待状态保持；取消后迟到的 ready 更新被拒绝；旧未完成记录补写待讨论且保留已完成操作。
- 可控 runner 断言讨论未达标时 runner/tool 均未被调用；WorkAgentLoop 直接入口同样不调用模型或工具。
- 讨论状态 JSON 的版本/非法字段边界、审批/附件元数据共存，以及上下文压缩后阶段、执行人和 DOCX 合同保持。
- 现有工作模式协调器、上下文、AgentLoop 和群聊 UI 集成测试继续覆盖资源锁、审批、目录授权、接力和私聊兼容路径。

## 验收矩阵

- A11：S2 已覆盖核心门禁。模型自述 tool/finish、旧检查点或理解 99% 都不能越过唯一协调器/AgentLoop 入口；请求版本、合同和角色身份不匹配时不会调用工具。
- A19：S2 已覆盖持久 JSON、上下文压缩、恢复、旧记录补足、跨群隔离和取消后迟到回调；旧完成产物不被清除或重放。完整页面动作去重和最终格式交付仍属于后续阶段。
- A03：私聊不触发群讨论状态；普通聊天仍不进入工作模式。
- A04–A10、A12–A20：S2 只提供状态/门禁承载或兼容边界，真实讨论发言、主动收集意见、补角色操作、Word 转换和完整提醒闭环留在计划的 S3–S7。

## S3 接入点与剩余风险

S3 应从 `WorkTaskCoordinator.updateDiscussionState(taskId, state)` 写入每轮讨论结果，使用 `participants`、`round`、`understandingEvidence`、`understandingPercent`、`openQuestions`、`blockers` 和候选/执行人字段；只有它把状态转换为 ready，现有 runner 才会启动。讨论回复必须携带当前 `requestRevision`，并在写入前确认任务未终止。S2 没有添加第二协调器、定时器或虚构角色，也没有开放提前执行的用户按钮。

尚未在本阶段验证真实多角色 API、插件安装、桌面授权或真实 DOCX 转换；这些属于后续阶段的实现与验收范围。S1 保留的多阶段接力仍需在 S3/S4 把“讨论确定的最终执行人”和阶段接力语义统一；S2 不允许通过放宽门禁来掩盖该差异。
