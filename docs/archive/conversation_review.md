# 对话复盘：重复问题与不足

## 1. 结论摘要

项目已经具备较完整的代码、测试和工作模式基础，但实际对话仍反复出现“没有真正执行、没有展示证据、没有保持上下文、自动聊天重复刷屏”四类问题。最值得优先修复的不是再增加一层提示词，而是把“完成”定义成可验证的状态，并让失败尽早、清楚、可恢复地暴露。

## 2. 数据事实

| 指标 | 结果 |
|---|---:|
| 角色 | 74 |
| 群组 | 8 |
| 总消息 | 783 |
| 用户消息 / AI 消息 | 180 / 603 |
| 对话 | 35 |
| 群聊 / 私聊 | 8 / 27 |
| 时间范围 | 2026-07-07 → 2026-07-09 |

消息集中在少数对话：`向日葵远控` 170 条、`张若晴` 私聊 151 条、`聊天群用户体验` 108 条、`相亲群` 98 条，四个对话合计 527 条，占归档的约 67%。这说明问题主要集中在自动群聊、长上下文私聊和工具交付场景。

## 3. 做得不好的地方

### P0：把“答应做”当成“已经完成”

在 [`聊天群用户体验`](conversations/group_聊天群用户体验_627be971-abd.md) 中，用户要求输出 MD 文件后，AI 多次说“快了”“11点准时推”“推了推了”，用户随后仍然问“放哪了 我看不到”。在同一对话里，用户对 `docs/agentic_live_test.md` 的“真正使用工具生成文件”请求精确重复 4 次；在 [`范晓萌`](conversations/dm_范晓萌_dm_63491e71-.md) 中，HTML 文件需求也出现“不要我复制、帮我写到这个文件中、再来一次”。

根因表现为：工具路由/bridge 失败后仍有自然语言承诺，或工具成功后没有把实际路径和验证结果作为唯一交付信号。改进门禁：没有 `workspace.patch` 成功返回、文件存在、文件内容检查和最终路径，就不能说“已生成”。

### P1：工具桥接失败后重复盲试

归档中出现“连接被拒绝”“连接超时”“本地工具桥接服务未启动”等结果；用户没有得到一次明确的“当前不能继续 + 启动命令 + 重试条件”的闭环，转而重复相同请求。项目文档和代码已经有 bridge、旧版 fallback、任务恢复等机制，但对话层的失败体验仍然不统一。

改进：工具任务开始前先做 bridge health check；失败后把失败状态持久化为任务状态，展示可复制的启动命令和下一步，不再次生成同一份文件，不让自动聊天接管工作请求。

### P1：自动群聊缺少有效去重和停机条件

[`向日葵远控`](conversations/group_向日葵远控_89c36ccc-bcf.md) 共 170 条消息，其中 AI 152 条但仅 39 个不同文本，至少 113 条是重复文本的额外出现。三个泛化开场句分别出现 28、27、24 次；大量回复只是“大家最近有什么新想法”“这个话题上我有点不同看法”，没有推进讨论。

改进：在持久化前对规范化正文做短窗口 hash 去重；同一群组/同一角色/同一话题连续命中重复模板时立即冷却；自动聊天只在有新信息、提及、关系动作或话题推进时继续；达到重复预算就暂停并显示原因。

### P1：长上下文私聊的记忆与事实一致性不足

[`张若晴`](conversations/dm_张若晴_dm_2d5feb41-.md) 151 条消息中，用户多次追问“还记得吗”“无限恐怖你忘记了”“你怎么不主动找我聊天”“前后对不上”，并反复测试当前时间。用户感知到的不是单次回答错误，而是长期关系、主动性和事实一致性没有形成稳定体验。

改进：每轮私聊前构造带来源和时间的短记忆卡，只注入与当前话题相关的事实；当前时间必须走真实时钟能力或明确声明不能可靠读取；关系/主动联系策略与普通回答分开测试，避免靠模型自行“记住”。

### P2：人设风格没有及时响应用户反馈

用户明确说“别那么专业”“自然点”“回答还是很 AI 味”，但角色仍容易回到职业化、答题式、短句问答式。项目已经有 `HumanizedPromptBuilder`、场景模式和关系记忆，但这些策略需要把用户的即时风格反馈作为可执行状态，而不是只作为一条历史消息。

改进：加入短期风格偏好（如自然、少提问、少职业术语），设定过期和覆盖规则；用对话回放测试“用户要求自然后，后续 5 轮是否仍自然”。

### P2：开发验证和用户可见验证没有完全闭环

现有审查文档多次记录 `flutter analyze`、`flutter test` 全绿，且 Agentic/WorkBuddy 有端到端测试；但对话仍出现文件不可见、bridge 不可用和重复催办。说明“代码测试通过”与“当前用户任务交付成功”是两种不同验收，不能用前者代替后者。

改进：将“业务交付验收”加入端到端测试：实际写文件、检查路径、读取文件、展示附件/链接，再验证任务状态为 completed。

## 4. 重复问题清单

| 重复问题 | 证据 | 可能根因 | 优先级 |
|---|---|---|---|
| 同一个文件请求反复发送 | `agentic_live_test.md` 精确重复 4 次，另有简化变体 2 次 | 未执行或未证明执行 | P0 |
| 用户持续询问进度/位置 | “还没好吗”“多久”“进度”“放哪了”“看不到” | 没有统一进度和交付协议 | P0 |
| bridge 连接拒绝/超时 | 多条工具失败消息 | 健康检查、启动、恢复和重试未统一 | P1 |
| 自动群聊重复模板 | `向日葵远控` 152 条 AI 消息 / 39 个唯一文本 | dedup、冷却、主题推进不足 | P1 |
| 记忆遗忘与前后矛盾 | `张若晴` 的家庭、阅读、时间、状态追问 | 历史检索和事实工具不足 | P1 |
| “太专业 / AI 味” | `张若晴`、`相亲群` 的风格反馈 | 风格反馈未进入短期策略 | P2 |
| 误把计划/承诺写成完成 | “马上推”“推了推了”后仍看不到产物 | 完成态没有产物门禁 | P0 |
| 评审反复发现低价值问题 | 代码审查中既有真实死代码，也有对旧行为的误报 | review 缺少旧版对照和证据分级 | P2 |

## 5. 改进顺序

1. 先修“真实交付门禁”：工具成功 → 文件存在 → 内容验证 → 路径交付 → 任务完成。
2. 再修 bridge 生命周期：开始前检查、失败可恢复、拒绝与失败分开、禁止盲目重复写入。
3. 增加自动聊天去重和重复预算，优先覆盖 `向日葵远控` 的回放。
4. 增加私聊记忆/时间一致性回放，不依赖模型自述“我记得”。
5. 最后做风格调节、成本估算、搜索和导入恢复等体验增强。

## 6. 尚未解决的结构性风险

- 导入/恢复尚未实现，归档目前是可读备份，不是可回写备份。
- 生产 release 数据与仓库 `data/*.hive` 的路径不同；本次只归档仓库开发数据。
- 消息正文可能包含个人信息，即使结构化密钥字段已排除，归档仍需按敏感文件管理。
- UI-heavy 的真实聊天行为仍主要依赖抽取逻辑测试，需补充端到端用户路径测试。
