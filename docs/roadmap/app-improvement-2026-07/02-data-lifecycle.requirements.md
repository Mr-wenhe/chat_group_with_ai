# 阶段 02 需求文档：数据生命周期一致性

状态：草案  
目标版本：待定

## 1. 阶段目标

让“删除角色”“删除群聊”“删除 API 配置”“清除所有数据”的实际结果与界面承诺完全一致，并为消息附件、记忆、关系、任务和设置建立明确的生命周期。

## 2. 背景与问题

- 删除群聊目前只删除群组主记录，消息、记忆、关系和索引可能残留。
- 删除角色目前只删除角色主记录，私聊消息、技能、任务、关系和群成员引用可能残留。
- 删除 API 配置与角色中的旧配置字段存在不一致。
- 删除消息或群聊时，已复制的媒体文件没有完整的引用回收机制。
- “清除所有数据”没有统一定义哪些偏好应保留、哪些工作模式/checkpoint 设置应删除。

## 3. 产品原则

- 删除范围必须在确认框中说清楚，不能说“所有数据”却只删一部分。
- 不可逆删除前提供影响预览；高价值数据优先提供导出入口。
- 删除操作必须幂等：中途失败后重试不会产生更坏状态。
- 用户偏好与用户内容分开定义，清空内容不应意外重置无关主题偏好，除非用户选择“恢复出厂设置”。

## 4. 范围

### 必须包含

- 群聊级联删除。
- 角色删除及群成员引用清理。
- 私聊删除/保留策略。
- API 配置删除、解绑和受影响角色预览。
- 单消息、群聊和全量清除后的附件垃圾回收。
- `app_settings` 键分类和清理规则。
- 删除失败、部分完成和重试提示。

### 本阶段不包含

- Git 中数据文件及历史追踪处理。
- 完整备份导入功能；属于阶段 04。
- 消息分页和数据库性能重构；属于阶段 03。

## 5. 删除语义

### R02-01 删除群聊

默认删除：群组、该群消息、群记忆、角色群记忆、群关系、群工作模式任务/工作区记录、已读/置顶/checkpoint 状态及无其他引用的附件。

### R02-02 删除角色

删除前展示：所在群数量、私聊消息数量、技能数量和任务数量。用户至少可以选择：

- 删除角色并从群组移除，保留历史消息为“已删除角色”。
- 删除角色及其私聊、技能、任务和相关记忆。

群聊历史消息是否一并删除由产品确认，默认建议保留并显示匿名占位身份，避免破坏群聊上下文。

### R02-03 删除 API 配置

- 展示引用角色数量。
- 支持取消、替换为另一配置、或确认解绑。
- 删除后不得使用旧 Key 回退。

### R02-04 清除数据

至少区分：

- 清除聊天内容。
- 清除角色/群聊/API 配置等全部用户内容。
- 恢复出厂设置（包含主题、TTS、目录等偏好）。

### R02-05 附件回收

- 仅删除不再被任何消息或任务引用的 APP 管理文件。
- 绝不删除用户原始选择文件或工作区中不归 APP 管理的文件。
- 设置页提供媒体占用统计和手动清理孤儿文件。

## 6. 非功能需求

- 删除 1 万条消息的会话时，UI 不应长时间无响应。
- 删除操作中途失败后，APP 可报告未完成项并允许安全重试。
- 所有删除路径必须有自动化测试覆盖。
- 数据模型变化必须兼容旧 Hive 数据。

## 7. 验收标准

- [ ] 删除群聊后，所有定义内的关联记录均不存在。
- [ ] 删除角色后，群组中不再出现悬空成员 ID。
- [ ] 删除配置后，没有请求继续使用该配置的旧 Key。
- [ ] 清除聊天内容不会误删主题/TTS偏好；恢复出厂设置会按定义清除。
- [ ] 附件回收只删除 APP 管理目录中的孤儿文件。
- [ ] 删除中断并重试后结果与一次成功执行一致。
- [ ] UI 提示文本与实际删除集合一致。

## 8. 待确认问题

- 删除角色时，群聊中的该角色历史消息默认保留还是删除？
- 删除群聊前是否强制提示导出，还是只提供可选按钮？
- “清除所有数据”是否默认保留 API 配置，以便快速重新开始？
- Agent 工作区生成文件属于聊天附件还是独立用户文件，删除任务时应如何处理？
