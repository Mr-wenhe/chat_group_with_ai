# 阶段 04 需求文档：完整备份、导入与恢复

状态：草案  
目标版本：待定

## 1. 阶段目标

让用户能够把 APP 的核心内容完整备份为可验证、可迁移的文件，并在新安装或数据损坏后安全恢复，而不是只有面向阅读的 Markdown/JSON 对话导出。

## 2. 背景与问题

- 当前导出面向分享和阅读，不是可恢复备份。
- 角色、群组、消息、记忆、关系、技能、工作模式配置和附件之间存在关联。
- 数据模型会继续演进，需要版本化格式和迁移策略。
- API Key 不应默认进入普通备份；若支持凭据备份必须单独加密和确认。

## 3. 用户价值

- 换设备、重装或清空前可以保存完整聊天资产。
- 导入前能看到备份内容、版本、大小和冲突，不会直接覆盖现有数据。
- 恢复失败不会破坏当前数据。

## 4. 范围

### 必须包含

- 创建完整备份包。
- 导入前校验、预览和兼容性检查。
- 恢复到空库。
- 导入到已有数据时的冲突策略。
- 附件包含、缺失和校验处理。
- schema version 和迁移。
- 备份原子性、失败回滚和恢复报告。

### 默认不包含

- API Key 明文备份。
- Git 中数据文件策略。
- 云端自动同步。
- 多人协作合并。

## 5. 备份内容

建议默认包含：

- API 配置公开元数据（不含 Key）
- 角色、群组、消息
- 群记忆、角色记忆、关系状态
- 角色技能、Agent 任务历史、工作模式会话配置
- 必要 app settings（已读、置顶、主题等按分类选择）
- APP 管理的消息附件
- manifest、schema version、APP version、创建时间、文件校验和

## 6. 核心流程

### R04-01 创建备份

- 用户选择备份范围：全部、仅角色/群组配置、指定会话。
- APP 先估算大小和附件数量。
- 生成临时包并完成校验后，再原子移动到目标位置。
- 完成页展示路径、大小、条目数量和校验状态。

### R04-02 导入预览

- 读取 manifest，不立即写库。
- 展示来源版本、数据数量、附件缺失、凭据缺失和兼容性。
- 明确提示导入后 API 配置需要重新绑定 Key。

### R04-03 冲突处理

至少支持：

- 仅恢复到空库。
- 跳过同 ID 条目。
- 复制为新 ID，并重写引用关系。

“直接覆盖现有条目”风险较高，是否提供由产品确认。

### R04-04 恢复与回滚

- 导入写入临时数据区或生成恢复计划。
- 全部校验成功后切换/提交。
- 失败时现有数据保持不变，并输出可读报告。

## 7. 安全与隐私需求

- 普通备份不包含 API Key。
- 备份包含完整对话和附件，创建/分享前必须明确提示敏感性。
- 若启用加密，密码不能保存在备份包内。
- 解压必须防止 zip slip、超大解压和恶意路径。

## 8. 验收标准

- [ ] 空库可恢复角色、群组、消息、记忆和附件，引用完整。
- [ ] 导入前可预览，不点击确认不会写入任何 Box。
- [ ] 普通备份全文搜索不包含测试 API Key。
- [ ] 损坏校验和、未知 schema 或恶意路径会被拒绝。
- [ ] 导入中途失败后原数据不变。
- [ ] 同一备份可重复导入，并按所选冲突策略产生可预测结果。
- [ ] 恢复完成生成条目数、跳过数、重映射数和错误报告。

## 9. 待确认问题

- 默认备份是否强制密码加密？
- Agent 任务日志和生成文件是否默认包含？
- 已读、置顶、主题等偏好是否默认迁移？
- 第一版是否只支持“恢复到空库”，把合并导入放到后续小版本？
