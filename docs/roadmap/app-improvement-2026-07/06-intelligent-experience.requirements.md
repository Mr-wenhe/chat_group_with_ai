# 阶段 06 需求文档：记忆、搜索与文档智能

状态：方向草案，建议在阶段 03–05 完成后再拆成独立版本  
目标版本：待定

## 1. 阶段目标

把“长期记忆、历史内容和用户文档”从后台黑盒能力变成用户可查看、可控制、可检索的知识层，让 APP 适合长期聊天和轻量工作协作。

## 2. 子目标与建议顺序

本阶段包含三个可独立交付的子目标，正式实施前可拆成 06A/06B/06C：

1. 记忆透明与控制。
2. 跨会话全局搜索。
3. 文档解析与可引用回答。

离线主动联系、无障碍和国际化作为本阶段后的增强候选，不应阻塞前三项。

## 3. 范围

### 本阶段包含

- 现有群记忆、角色记忆和关系状态的可见、可编辑、可删除能力。
- 基于本地索引的跨会话关键词搜索和消息定位。
- 文本类文档解析、片段检索和来源引用；二进制办公文档按独立解析器逐步加入。

### 本阶段不包含

- Git 中数据文件及历史追踪处理。
- 默认依赖外部 embedding 服务的语义搜索。
- 未经用户明确设计的后台 LLM 调用或“伪离线”主动联系。
- 与前三个子目标无关的全面 UI 改版。

## 4. 子目标 A：记忆透明与控制

### 用户需求

- 查看一个角色在某群/私聊中记住了什么。
- 区分事实、偏好、关系变化和摘要。
- 编辑错误记忆、删除敏感记忆、锁定不应被自动覆盖的记忆。
- 在下一次请求前知道将使用哪些记忆。

### 功能需求

- 角色记忆详情页和群记忆详情页。
- 记忆来源、更新时间、适用会话和置信/状态信息。
- 编辑、删除、固定和暂停自动记忆。
- “忘记这个话题/关于我的内容”快捷操作。
- 删除后不能继续从旧摘要或角色 legacy 字段注入。

### 验收

- [ ] 用户能查看并删除一条记忆，后续 prompt 不再包含它。
- [ ] 固定记忆不会被自动摘要覆盖。
- [ ] 自动记忆关闭后不再产生新的记忆 API 调用。

## 5. 子目标 B：跨会话全局搜索

### 用户需求

- 从一个入口搜索群聊、私聊、角色、附件和时间范围。
- 按发送者、会话、日期、@提及、附件类型过滤。
- 点击结果直接加载并定位目标消息。

### 功能需求

- 第一版采用本地关键词索引，不依赖联网。
- 支持中文、英文、文件名和角色名。
- 搜索结果展示会话、发送者、时间和高亮片段。
- 索引可重建，可从设置页查看状态和清除。
- 语义搜索作为可选后续能力，必须说明模型和隐私成本。

### 验收

- [ ] 5 万条消息数据集上搜索 P95 < 500 ms（设备待定）。
- [ ] 结果跳转能加载未在当前分页窗口内的目标消息。
- [ ] 删除消息/会话后索引不会返回幽灵结果。

## 6. 子目标 C：文档解析与可引用回答

### 用户需求

- 发送 PDF、Word、Excel、Markdown/文本后，AI 能理解内容，而不只是看到文件名。
- 回答能指出来源文件和页码/工作表/段落。
- 用户能看到文件是否已解析、哪些内容因限制未处理。

### 功能需求

- 支持格式优先级建议：TXT/MD/JSON/CSV → PDF → DOCX/XLSX。
- 解析在本地优先完成，生成结构化片段和来源定位。
- 长文档分块、大小/页数限制和取消。
- 只把与问题相关的片段发送给 LLM。
- 文档索引与消息/会话生命周期一致，可删除和重建。

### 验收

- [ ] 支持格式能提取文本并显示解析状态。
- [ ] 回答引用能定位到文件和片段。
- [ ] 超限、加密或损坏文件有明确提示，不会卡死聊天。
- [ ] 删除附件后，其解析缓存和索引一并清除。

## 7. 后续增强候选

- 离线主动联系：需要本地预生成通知或服务端 push 的独立架构，不以“后台偷偷调用 LLM”实现。
- 无障碍：屏幕阅读器语义、键盘导航、动态字体和色彩对比。
- 国际化：提取硬编码中文、locale 和日期/数字格式。
- 可选本地 embedding：在设备能力允许且用户同意时提供语义搜索。

## 8. 非功能需求

- 记忆和文档索引均可本地清除，不成为不可见的数据副本。
- 文档正文、搜索查询默认不发送到除所选 LLM/搜索服务外的第三方。
- 大文件解析不得阻塞 UI，必须有进度和取消。
- 索引是可重建缓存，不应成为唯一事实来源。

## 9. 整体验收标准

- [ ] 06A、06B、06C 可以独立启用、验收和回滚，不形成必须一次上线的大版本。
- [ ] 用户可以查看并清除记忆、搜索索引和文档解析缓存。
- [ ] 数据删除、备份恢复和索引更新之间不存在幽灵结果或旧记忆回流。
- [ ] 所有后台处理均有进度、取消、失败提示和资源上限。
- [ ] analyze/test 全绿，并完成目标平台 release build 验证。
