# 阶段 04 技术方案：完整备份、导入与恢复

状态：提议  
对应需求：`04-backup-restore.requirements.md`

## 1. 格式决策

建议使用 ZIP 容器，内部采用稳定 JSON 文档和 `attachments/` 目录：

```text
backup.zip
├── manifest.json
├── data/
│   ├── api_configs.json
│   ├── characters.json
│   ├── groups.json
│   ├── messages.jsonl
│   ├── memories.json
│   ├── relationships.json
│   ├── skills.json
│   └── work_mode.json
└── attachments/
    └── <content-id>.<ext>
```

消息使用 JSON Lines 便于流式写入大历史。附件名称使用内容 ID，不信任原文件名。manifest 记录格式版本、条目数、每个文件 SHA-256 和可选加密信息。

## 2. 服务边界

- `BackupExportService`：读取快照、流式序列化、复制附件、生成校验。
- `BackupInspector`：仅读 manifest/索引，生成预览。
- `BackupMigrationRegistry`：逐版本转换到当前导入模型。
- `RestorePlanner`：冲突检测、ID 映射和预计写入。
- `RestoreExecutor`：在隔离区写入、校验、提交或回滚。

业务模型不得直接依赖 ZIP 库；使用中间 DTO，避免 Hive adapter 成为公开备份格式。

## 3. 一致性方案

Hive 缺少多 Box 原子事务。首版优先考虑：

1. 导入到新的临时 Hive 目录。
2. 完整打开并验证所有 Box、引用和附件。
3. 关闭当前 Box。
4. 原子切换数据目录或执行带备份的文件替换。
5. 启动失败时恢复旧目录。

若平台无法安全切换目录，则使用持久化 RestoreJob 和逐 Box staging key；不得直接边解析边覆盖当前数据。

## 4. ID 重映射

复制导入时建立 `oldId -> newId` 映射，按依赖顺序处理：

1. API 配置公开元数据。
2. 角色。
3. 群组和成员引用。
4. 消息与引用回复。
5. 记忆、关系、技能、任务和工作区。
6. 设置索引。

所有引用在提交前运行完整性校验。

## 5. 安全控制

- 限制压缩包总大小、单文件大小、条目数和解压后膨胀比。
- 拒绝绝对路径、`..`、符号链接和重复覆盖路径。
- API Key/Authorization 字段使用明确 denylist 加结构白名单双重检查。
- 可选加密应使用成熟认证加密格式；在算法决定前写 ADR，不自定义密码学协议。

## 6. 实施任务

### Task 04-1：定义 v1 manifest 和 DTO

**验收：** 格式样例、字段说明、兼容规则和秘密排除规则确定。  
**验证：** schema/DTO round-trip 测试。  
**依赖：** 阶段 02 模型生命周期明确。  
**预计范围：** M。

### Task 04-2：实现无附件的空库备份/恢复

**验收：** 核心实体 round-trip 后引用一致。  
**验证：** 固定 fixture 导出、清空临时库、恢复并深比较。  
**依赖：** Task 04-1。  
**预计范围：** M。

### Task 04-3：加入附件内容寻址和校验

**验收：** 重复附件去重，缺失/损坏可报告，路径攻击被拒绝。  
**验证：** 临时目录和恶意 ZIP fixture。  
**依赖：** Task 04-2。  
**预计范围：** M。

### Task 04-4：导入预览和恢复报告 UI

**验收：** 未确认不写库；完成后显示可核对报告。  
**验证：** Widget 测试与人工恢复演练。  
**依赖：** Task 04-2、04-3。  
**预计范围：** M。

### Task 04-5：冲突复制和 ID 重映射

**验收：** 导入到已有库不会覆盖现有条目，全部引用指向新 ID。  
**验证：** 重复导入两次；引用完整性扫描。  
**依赖：** Task 04-2。  
**预计范围：** M/L，应拆实体组实施。

### Task 04-6：可选加密

**验收：** 无密码不可读取；错误密码不写任何数据；敏感临时文件被清理。  
**验证：** 加解密向量、错误密码和中断测试。  
**依赖：** 产品确认；Task 04-1 至 04-4。  
**预计范围：** M，需单独 ADR。

## 7. 检查点

- [ ] v1 格式经人工评审并冻结。
- [ ] 空库 round-trip 全绿。
- [ ] 恶意包和损坏包测试全绿。
- [ ] 至少完成一次真实开发数据副本恢复演练，不触碰当前数据目录。

## 8. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 备份格式绑定 Hive 实现 | 高 | 使用稳定 DTO/schema，不导出 Hive 二进制 |
| 大附件导致内存暴涨 | 高 | 流式压缩/解压，禁止一次读入全部包 |
| 跨 Box 恢复部分成功 | 严重 | 临时数据目录验证后切换；保留旧目录直到新库启动成功 |
| 冲突映射遗漏引用 | 高 | 中央映射表和提交前引用完整性扫描 |
